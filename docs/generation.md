# ConT가 만들어 내는 것의 자리

> 상태: 보조

ConT가 만들어 내는 것은 대화, 코드, 이미지, 물리 이미지, 영상, 3D CAD다 (ARCHITECTURE.md 정체성).
이 문서는 그 여섯 가지를 **어느 모듈이 만들고, 숫자는 어디서 오고, 어떤 지위로 내보내는지** 정한다.
모듈(C1~C7)의 경계는 바꾸지 않는다. 여섯 가지 모두 지금 있는 모듈 안에 자리가 있다.

## 출처

이미지·영상에 관한 규칙은 보관된 옛 저장소 `goosang-jung/Manufacturing-Physical-AI`의
`docs/architecture/01_CONT_PRODUCT_AND_UX_ARCHITECTURE.md`(4.2 이미지·영상, 4.5 상태 지위, Dynamic Surface 규율, Video truth classes)에서 가져왔다.
"물리 이미지"라는 말은 옛 저장소 다섯 곳 어디에도 없다. 아래 정의는 대표의 2026-11-22 정리를 이 문서가 풀어 쓴 것이며, **대표의 확인이 필요하다.**

## 1. 여섯 가지의 자리

| 만드는 것 | 뜻 | 만드는 모듈 | 내용이 나오는 곳 | 지금 상태 |
|---|---|---|---|---|
| 대화 | 묻고 답하고, 말로 설계를 바꾼다 | C1 대화·조율 (`cont.dialogue`, `cont.llm`) | 숫자는 팩의 답변 묶음. LLM은 말만 다듬는다 | 체결·진단에 있음 |
| 코드 | 결과를 다시 만들 수 있는 입력·스크립트 | C1이 조율, 내용은 C2·C3·C5 | 답변 묶음의 입력(`inputs`)과 형상 명세 | 없음. 뜻부터 정해야 한다 (3절) |
| 이미지 | 대상의 겉모습을 그린 그림 | C4 표현 (`cont.view`) | C5의 형상 명세 | 3D 화면만 있음. 그림 파일 내보내기 없음 |
| 물리 이미지 | 물리 상태(응력·압력·온도 등의 분포)를 그린 그림 | C4 표현 (`cont.view.field_image`) | C3가 계산한 물리장. 지위는 그 물리장의 지위를 따른다 | 체결에 하나 있음 (판의 압축 응력 분포) |
| 영상 | 시간이나 조건에 따라 변하는 모습 | C4 표현 | 답변 묶음을 조건을 바꿔 가며 이어 붙인 것 | 화면 안의 전환만 있음. 영상 파일 없음 |
| 3D CAD | 형상과 CAD 파일 | C5 형상 (`cont.shape`) | 치수 → 형상 명세 → 메시·STEP·STL | 체결에 있음 |

## 2. 지켜야 할 것

1. **물리를 담은 그림과 영상은 계산 결과에서만 나온다.** 물리 이미지와 물리 영상은 팩의 답변 묶음, 물리장, 형상 명세를 C4가 그린 것이다.
   생성 모델(이미지·영상 생성 AI)이 그린 그림에 물리값을 실어 내보내지 않는다. "LLM은 물리값을 만들지 않는다"와 같은 규칙이다.
2. **그림과 영상에도 지위를 붙인다.** 같은 "이미지", 같은 "영상"이라도 얻은 방법이 다르면 같은 것으로 보이지 않게 한다.

   | 종류 | 뜻 | 지위 |
   |---|---|---|
   | 관측 이미지·영상 | 실제 카메라·열화상·검사 영상. ConT가 만든 것이 아니라 받은 것이며 물리 상태의 증거로 쓴다 | 관측 |
   | 물리 이미지·영상 | 계산하거나 복원한 물리 상태를 그린 것 | 추정·해석·예측 가운데 그 상태의 지위 |
   | 생성 이미지·영상 | 생성 모델이 만든 설명·시나리오용 그림 | 생성 후보. 물리의 근거로 쓰지 않는다 |

3. **근거가 없으면 그리지 않는다.** 그릴 물리장이나 형상 명세가 없으면 그럴듯한 그림으로 채우지 않고 "보일 결과가 없다"고 한다.
4. **생성 모델은 어댑터로만 부른다.** 이미지·영상 생성 모델을 쓰게 되면 LLM과 같은 방식으로 한다: 공급자 SDK는 어댑터 안에서만,
   공급자는 `config/`와 환경 변수로, 테스트는 가짜 공급자로. 어댑터는 생성형 AI 공통 기반(Do Intelligence)에 둔다.
5. **미리보기가 먼저다.** 그림·영상·3D는 작게 먼저 보이고, 크게 보는 것은 사용자가 눌렀을 때만이다. 한 번에 크게 펼치는 것은 하나다.
6. **화면들은 같은 시점과 같은 판(revision)을 본다.** 한쪽에서 시점이나 판을 옮기면 이어진 그림·그래프·3D가 같이 옮겨 간다.

## 3. 아직 정하지 않은 것

- **"물리 이미지"의 뜻.** 이 문서는 "물리 상태의 분포를 그린 그림"으로 풀었다. 대표가 뜻한 것이 다르면(예: 물리 법칙을 지키게 만든 생성 이미지) 1절과 2절을 고친다.
- **"코드"의 뜻.** 두 가지로 읽힌다. (가) 결과를 다시 만들 수 있는 입력·스크립트, (나) 일반 프로그램 코드 생성.
  이 문서는 (가)로 적었다. (나)라면 C1과 LLM의 일이 되고 물리 규칙과는 따로 다룬다.
- ~~물리장을 담을 자리.~~ **넣었다 (2026-11-23).** 공통 결과 형식에 `Field`(면 위의 격자 값, 지위 포함)가 들어갔다. 공간(3D)에 퍼진 값과 시간에 따라 변하는 값은 아직 담지 못한다.
- ~~물리장을 내는 계산.~~ **체결에 하나 넣었다 (2026-11-23).** 판 안의 응력 분포를 축대칭 수치해석으로 낸다 ([fastening_field.md](fastening_field.md)). 볼트 안의 분포, 접촉(벌어짐)은 아직 풀지 않는다.

## 4. 체결에서 먼저 할 수 있는 것 (제안, 결정 아님)

| 순서 | 만들 것 | 필요한 것 | 크기 |
|---|---|---|---|
| 1 | 이미지: 3D 화면과 단면도를 그림 파일로 내보내기 | 지금 있는 것으로 충분 | 작다 |
| 2 | 영상: 토크를 올려 가며 체결력·응력이 변하는 모습을 영상 파일로 | 지금 있는 계산을 조건을 바꿔 가며 반복 | 작다 |
| 3 | 물리 이미지: 판과 볼트 안의 응력·압력 분포 | 물리장을 담는 형식 + 축대칭 수치해석 | 판은 완료. 볼트와 접촉은 남음 |
| 4 | 생성 이미지·영상 (설명용) | 생성 모델 어댑터 | 따로 정한다 |

1과 2는 "해석"한 값을 그린 것이고, 3이 되어야 정본이 말하는 "내부는 어떤 상태인가"에 그림으로 답한다.
