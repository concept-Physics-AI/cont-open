# 체결 팩: 화면과 대화로 바꾸기

> 상태: 보조

볼트 조인트의 계산 결과를 그림으로 보고, 말로 값을 바꾸면 다시 계산한다.
2026-11-23 대표 결정으로 남은 체결 슬라이스 가운데 화면(5)과 대화로 수정(3)을 먼저 했다. 기준값 대조(2), 설계 추천(4), 3D CAD는 그다음이다.

## 대화 중심 화면 (기본 화면)

`src/cont/view/fastening_app.py`. 말하는 곳을 가운데에 두고, 결과는 그 옆의 카드 한 장에 모았다. 아래 "움직이는 한 화면"의 3D 보기와 값의 지위 규칙은 그대로 쓴다.

**구성**

| 곳 | 내용 |
|---|---|
| 처음 | "무엇을 설계할까요?", 입력창, 시작할 말 네 가지. 말을 하면 대화와 결과가 열린다 |
| 왼쪽 목록 | 새 설계, 지금 설계, 모형 설명·코드 바로가기 (주소는 `config/fastening/default.yaml`의 `app`) |
| 대화 | 내 말은 오른쪽 말풍선, 답은 풀어 쓴 문장. 바뀐 값은 최대 셋(이전 → 지금), 추천은 누르는 단추 |
| 추천 문구 | 입력창 위에 다음에 할 만한 말. 맨 앞이 가장 권하는 말이다 |
| 결과 카드 | 제목, 그림(3D CAD · 단면 · 그래프 · 물리 이미지), 숫자 셋, 묶음 단추 셋(값 전체 · 믿어도 되는가 · 현장에서 재려면) |

**고정되는 곳과 흐르는 곳**

- 넓은 화면에서는 쪽 전체가 흐르지 않는다. 흐르는 곳은 대화와, 결과에서 펼친 묶음의 안쪽 둘뿐이다. 입력창과 추천 문구, 그림과 숫자 셋은 늘 제자리에 있다.
- 새 답이 오면 맨 아래를 보고 있을 때만 따라 내려간다. 위를 읽고 있으면 그대로 두고 "최신 답으로" 단추를 띄운다.
- 묶음은 한 번에 하나만 열린다. 열면 그림 상자가 보기 이름 줄만 남기고 위로 접혀, 묶음의 글이 넓게 보인다. 접힌 줄이나 보기 이름을 누르면 그림이 다시 펼쳐진다. 그림을 여는 말("응력 분포를 보여 줘")을 하면 묶음을 닫고 그림을 키운다.
- 3D 위에서 휠을 굴리면 확대만 되고 쪽은 흐르지 않는다.
- 좁은 화면(900px 이하)에서는 위의 이름 줄과 아래의 입력창만 고정한다. 결과 카드는 가장 새 답 바로 아래, 대화 안에 놓이고 전체가 한 줄기로 흐른다. 추천 문구는 옆으로 민다.

**말**

- 답은 문장으로 쓴다 (`src/cont/dialogue/fastening_talk.py`). "조임 토크를 75 N·m로 올렸습니다. 볼트 응력이 항복강도를 넘었습니다." 문장 속 숫자는 모두 계산 결과에서 온다. LLM이 쓰는 글이 아니라 규칙으로 만든 글이다.
- 추천 문구는 지금 상태에서 규칙으로 고른다: 추천이 나와 있으면 "1번으로", 안전율이 1.0 아래면 그 안전율을 올리는 말, 그 밖에는 토크를 올리는 말. 문구 속의 값(1.5, +25 N·m)은 `config/fastening/default.yaml`의 `dialogue`에 둔 예시 값이며 판정 기준이 아니다.
- 설계를 바꾸지 않고 화면만 여는 말이 있다: "응력 분포를 보여 줘"(물리 이미지), "이 결과를 믿어도 돼?"(믿어도 되는가), "현장에서는 무엇으로 재야 해?"(현장에서 재려면).

**모양새**

- 색은 둘만 쓴다. 바뀐 곳과 가장 권하는 문구를 알리는 황동색, 경계(1.0)를 넘었을 때의 빨강. 값의 지위는 숫자마다 붙이지 않고 제목 옆 한 줄("계산값 · 검증 전")로 적으며, 전체는 "믿어도 되는가"에 있다.
- 숨은 물리 보기에서 볼트의 색은 회색에서 황동색으로 가는 한 가지 계열이다. 눌리는 영역은 비쳐 보이게 그려 그 안의 볼트가 보인다.
- 글꼴은 IBM Plex Sans KR (인터넷이 없으면 기기의 기본 글꼴).

**공개 시연 (서버 없이 파일 하나)**

`--out`으로 낸 파일은 추천 문구를 따라갈 수 있는 대화를 미리 계산해 싣는다 (`serve_fastening.tree`). 싣는 설계 상태의 수에 한도가 있어, 그 너머로 가는 문구는 나오지 않는다. 직접 친 말은 계산하지 못하므로, 코드를 받아 서버로 띄우라고 안내한다.

**이미지로 저장**: 그림 위의 "이미지 저장"을 누르면 지금 보고 있는 그림(3D CAD · 단면 · 그래프 · 물리 이미지)과 숫자 셋을 한 장(1600 × 1080 PNG)으로 내려받는다. 그림에는 "계산값 · 검증 전"이 함께 들어간다. 브라우저 안에서 만들며 서버로 보내지 않는다.

**물리 이미지의 색**: 어두운 청회색에서 황동색으로 가는 한 가지 계열이다. 값이 클수록 밝다. 0보다 작은 곳(당겨지는 것으로 계산된 곳)만 청회색으로 따로 칠한다.

**4D (조이는 과정)와 영상**: "4D" 보기는 조임 토크를 0에서 지금 값까지 나눠(`config/fastening/default.yaml`의 `process`), 토크마다 같은 계산식으로 다시 계산한 값을 눈금으로 오간다 (`src/cont/packs/fastening/process.py`). 재생하면 볼트의 색(응력 ÷ 항복강도)과 숫자(조임 토크, 체결력, 볼트 늘어남)가 따라 바뀐다. "영상 저장"은 그 재생을 글자와 함께 녹화해 내려받는다 (1280 × 720, 브라우저 안에서 만들며 대개 WebM).

- 이것은 시간에 따른 거동의 해석이 아니다. 조이는 동안의 마찰 변화, 속도, 조인 뒤의 풀림은 담지 않는다. 운전 하중이 걸리기 전의 값이다.
- 여기의 "조립 시 응력 ÷ 항복강도"는 조일 때의 값(비틀림 포함)이라, 결과 카드의 운전 시 값과 다를 수 있다.
- 형상은 변하지 않는다. 볼트의 늘어남은 숫자로만 보인다 (그림으로 보이기에는 너무 작다).
- 영상 저장은 브라우저가 녹화 기능(MediaRecorder)을 지원해야 한다. 지원하지 않으면 그렇게 알린다.

예전 화면은 서버의 `/live`와 `--out ... --live`로 남아 있다.

## 움직이는 한 화면 (예전 기본 화면)

처음 만든 화면은 위에서 아래로 긴 문서였고, 말을 보낼 때마다 화면 전체를 새로 그렸다. 대표가 직접 써 보고 준 의견은 이랬다:
고정된 화면이 아니라 오가면서 그래프·그림·3D가 변하는 것을 봐야 한다, 지나간 글은 날려 버리고 특별한 내용이 자연스럽게 나타나야 한다,
대화의 내용이 복잡하고 어렵다. 그래서 기본 화면을 바꿨다 (`src/cont/view/fastening_live.py`).

- **한 화면**: 왼쪽에 보기(3D 형상, 단면, 체결 선도, 토크-체결력)를 오가는 무대, 오른쪽에 큰 숫자 세 개와 안전율 막대. 긴 표와 계산 근거는 "자세히"에 접혀 있다.
- **그 자리에서 변한다**: 말을 보내면 화면을 새로 열지 않는다. 3D 형상은 옛 치수에서 새 치수로 변하고, 숫자는 굴러가며 바뀌고, 막대는 늘어나거나 줄어든다. 바뀐 숫자 칸은 잠깐 테두리가 켜진다.
- **지나간 말은 사라진다**: 내가 한 말은 잠깐 떴다가 날아간다. 앞의 답은 새 답이 올 때 날아가고, 고를 것이 없는 답은 9초 뒤 스스로 사라진다. 마우스를 올리면 머문다.
- **답은 한눈에**: 한 줄 결론, 가장 크게 달라진 값 최대 네 개(이전 → 지금), 눈여겨볼 것 하나. 긴 글은 답 안의 "자세히"에 있다.
- **눈여겨볼 것**: 안전율이 1.0을 넘나들면 그것을 맨 앞에 알린다. 그런 일이 없으면 가장 크게 달라진 값 하나에 테두리를 준다. 합격·불합격은 말하지 않는다.
- **추천은 누르는 단추**: "1번", "2번"을 누르면 적용된다. 무엇을 바꿀지 못 찾았을 때는 예시 말이 단추로 나온다.
- **어디가 바뀌었는지 표시한다** (대표의 두 번째 의견). 바뀐 곳의 표시는 다음 말을 할 때까지 남는다.
  - 3D: 바뀐 부품이 잠깐 빛나고, 그 부품에 "볼트 M10 → M12", "머리 쪽 판 15 → 20 mm" 같은 이름표가 붙는다. 하중처럼 부품이 없는 변화는 화면 위쪽에 글로 뜬다.
  - 단면, 체결 선도, 토크와 체결력: 바꾸기 전의 모습을 점선으로 겹쳐 그린다. 내용이 바뀐 보기의 이름 옆에는 점이 붙고, 열어 보면 없어진다.
  - 숫자: 바뀐 줄 왼쪽에 막대가 서고, 얼마나 바뀌었는지(▲ 3,866, 이전 38,660)가 아래에 붙는다.
  - 안전율: 바꾸기 전 값의 자리에 점선 눈금이 남는다.
- **답은 그림을 가리지 않는다** (대표의 세 번째 의견). 답은 그림 아래, 입력 칸 위에 놓인다.
- **보이는 물리와 숨은 물리를 나눈다** (대표의 세 번째·네 번째 의견). 정의와 규칙은 [hidden_physics.md](hidden_physics.md)에 있고, 옛 저장소의 정본에서 가져왔다.
  - **값의 지위를 적는다.** 체결에는 센서가 없어 "관측"과 "추정"이 아니라 "입력"과 "해석"이다. 묶음마다 지위가 붙고, 3D에는 "숨은 물리 해석 · 관측 없음 · 검증 전"이 늘 보인다.
  - **핵심 숫자는 셋이다.** 조립 체결력(마찰에 따른 범위와 함께), 볼트 응력 ÷ 항복강도, 가장 낮은 안전율. 나머지는 눌러서 연다:
    보이는 물리(입력), 숨은 물리(해석), 결과(안전율), 이 결과를 믿어도 되는가. 닫힌 묶음 안에서 값이 바뀌면 이름 앞에 점이 붙는다.
  - **이 결과를 믿어도 되는가**: 값의 지위, 근거 데이터, 사용 모델, 가정, 불확실성, 물리잔차, 검증 상태, 적용 범위, 실패 조건.
  - **3D의 "숨은 물리 보기"**(기본으로 켜짐): 판을 비쳐 보이게 하고, 판이 눌리는 영역(VDI 2230의 변형 원뿔)을 드러내고, 볼트를 등가응력 ÷ 항복강도로 칠한다.
    주 물리장 하나(형상) 위에 보조 둘(눌리는 영역, 볼트의 응력 색)이다. 눌리는 영역은 계산 모형의 모양이며 해석(FEM)으로 얻은 응력 분포가 아니다.
  - **추천은 "생성 후보 (검증 전)"로 표시한다.**
- **모양새**: 무대는 CAD 작업 화면처럼 어둡게, 읽는 값은 밝은 바탕에 선으로만 나눴다. 강조색은 황동색 하나이고 "바뀐 곳"에만 쓴다. 1.0 아래로 내려간 값에만 붉은색을 쓴다.
- 움직임을 줄이도록 설정한 기기에서는 움직임 없이 바로 바뀐다.
- 예전의 긴 문서형 화면은 서버의 `/classic`과 `--out ... --classic`으로 남아 있다.

## 쓰는 법

```
python -m cont.dialogue.serve_fastening                  # 브라우저에서 http://127.0.0.1:8766
python -m cont.dialogue.serve_fastening --llm            # 말 읽기에 LLM을 쓴다 (config/llm의 기본 공급자)
python -m cont.dialogue.serve_fastening --out demo.html  # 추천 문구를 따라갈 수 있는 시연을 파일 하나로
```

```python
from cont.dialogue.fastening_chat import Session
from cont.dialogue.serve_fastening import example
from cont.view import render_fastening

s = Session(*example())                 # M10 10.9, 강판 15 mm 두 장
t = s.say("M12로 바꾸고 토크 80으로")   # t.changes, t.reply, t.before, t.after
render_fastening(s.joint, s.load, s.answer, before=t.before)
```

## 화면에 있는 것

- **3D 형상**: 치수에서 만든 볼트·너트·판 두 장. 끌어서 돌리고 휠로 확대한다. 판은 안이 보이게 4분의 1을 잘라 낸다 ([docs/shape.md](shape.md)).
- **단면**: 같은 형상을 치수 축척에 맞춘 2D 그림으로.
- **체결 선도**: 볼트가 늘어난 양과 판이 눌린 양, 조립 체결력, 운전 하중을 볼트와 판이 나눠 받는 몫.
- **토크-체결력**: 마찰 산포에 따른 체결력의 띠, 조임 중 등가응력이 항복강도에 이르는 체결력.
- **안전율**: 항복, 벌어짐, 미끄럼, 면압, 피로. 값과 1.0의 위치만 보인다. **합격·불합격은 표시하지 않는다** (허용 기준은 아직 정하지 않았다).
- **물리량 표**: 값을 바꾼 뒤에는 "바꾸기 전" 값을 함께 보인다.

## 말로 바꿀 수 있는 것

| 말의 예 | 바뀌는 것 |
|---|---|
| "M12로 바꿔" | 규격 (피치와 구멍 지름은 표준값으로 돌아간다) |
| "강도 등급 8.8", "12.9급으로" | 강도 등급 |
| "토크 80으로" | 조임 토크 (N·m) |
| "머리 쪽 판 두께 20", "너트 쪽 판 12", "판 두께 18" | 판 두께 (mm) |
| "바깥지름 50", "축부 길이 10" | 체결부 바깥지름, 축부 길이 (mm) |
| "마찰 0.12", "마찰 0.10~0.14" | 나사면·좌면 마찰계수, 마찰 범위 |
| "축방향 하중 8 kN", "축직각 하중 2000" | 운전 하중 (N) |
| "판 사이 마찰 0.2", "함몰량 0.01" | 미끄럼·체결력 손실에 쓰는 값 |

## 지키는 원칙

- 말에서 뽑는 것은 "무엇을 얼마로 바꿀지"뿐이다. 계산은 체결 팩이 다시 한다.
- LLM 없이도 된다. LLM을 쓰면 LLM은 바꿀 항목을 JSON으로만 답하고, 허용한 항목과 형식이 아니면 버리고 규칙으로 다시 읽는다. LLM이 계산 결과를 만들 수 없다.
- 표준 데이터에 없는 규격처럼 바꿀 수 없는 값이면 조인트를 그대로 두고 이유를 말한다.
- 서버는 내 PC(127.0.0.1)에서만 받고, 조인트 하나를 한 사람이 다루는 것을 전제로 한다.

## LLM에 전달하는 문맥

LLM으로 설계 입력을 읽을 때 현재 조인트·하중·단위·유효한 추천 목록과 최근 대화를 함께 보낸다.
과거 대화에는 사용자 요청과 **실제로 적용된 변경**을 따로 담는다. 실패한 요청은 실패로 남고,
검사를 통과하지 못한 공급자 원문이나 임의의 계산 결과를 다음 문맥으로 넘기지 않는다.
오래된 대화가 빠져도 현재 설계 입력은 유지된다.

- `config/dialogue.yaml`: 기본 최근 왕복 10개, 메시지 내용 합계 16,000글자. 토큰 한도가 아니다.
- 과거 대화는 사용자·처리 결과 쌍을 통째로 줄인다. 현재 질문과 현재 상태는 잘라내지 않는다.
- 현재 질문·상태만으로 예산을 넘으면 공급자를 호출하지 않고 기존 규칙 해석으로 돌아간다.
- `/reset`은 이력을 비우고 예제 설계로 돌아가며 공급자와 문맥 제한 설정은 유지한다.
- 검증은 기록형 시험 공급자로 문맥 전달·재계산·실패 기록·세션 객체 간 분리·HTTP 초기화를 확인한다.
  실제 공급자의 지시어 해석 정확도, 사용자별 HTTP 세션, 영속 저장, 열·진단 대화의 통합 문맥은 별도 작업이다.
