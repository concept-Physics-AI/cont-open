# 보관 개발 자산의 후속 적용 명세

> 상태: 참고

**현재 채택 우선순위 (2026-11-25):** 아래 A 번호와 기존 P 표시는 보관 자산의 추적·개별 위험 순위다. 제품 전체의 착수 순서는 [roadmap.md](roadmap.md)의 P1~P6이다. 대화·계획·실제 생성·선택 편집·일관성·저장을 먼저 연결하고, 산업별 모델·실측 검증 자산은 해당 전문 기능에 적용한다.

2026-11-25 보관 소스·복구 후보·학습 기록을 `cont-open`의 `e8e7c5d`에서 조사하기 시작했고, 검토 중 올라온 `5c383cc`까지 다시 대조했다. 원본 저장 위치, 고객 자료, 모델 가중치와 내부 보고서는 포함하지 않는다. 이 문서는 구현 완료 목록이 아니다. 기존 37개 작업([adoption_tasks.md](adoption_tasks.md), PR #71로 main 반영)을 상세화하며 중복되는 항목은 같은 작업에 연결한다.

## 적용 기준

- 현재 C1~C7, `PhysicsAnswer`, `cont.llm`, `RunStore`를 유지한다. 옛 서비스·결과 형식을 통째로 추가하지 않는다.
- 파일이 있다는 사실, 함수가 실행됐다는 사실, 실제 공급자/해석기가 실행됐다는 사실, 현장 성능을 구분한다.
- 보관 자료의 합격 기록은 그때의 입력·버전·시험 범위에만 해당한다. 현재 제품의 인수 결과로 대신하지 않는다.
- 아래 `구현 PR`은 코드와 회귀시험을 마련한 상태이며 main 병합·운영 반영과 다르다. `기존 일부`는 이미 있는 기능을 재사용하되 남은 범위를 구현한다. `후속`은 아직 구현하지 않았다.
- P0는 현재 결과의 정확한 연결과 입력 처리, P1은 사용 가능한 제품 흐름, P2는 데이터·해석기·현장 평가가 필요한 확장이다. 현재 로드맵의 물리 영역 순서를 바꾸지 않는다.

## 가져오지 않는 것과 보완할 것

- 참조만 준비하고 `not_run`을 반환하는 시각 생성 코드를 실제 이미지·영상 생성기로 등록하지 않는다.
- 문자열 매칭 검색을 임베딩 검색·재순위 모형 완료로 적지 않는다. 문서 충돌 검사는 제한된 명시적 값 비교부터 평가한다.
- 복구 기록의 API 연동 성공, 모의 UI 시험 성공, 실제 브라우저의 사용자 흐름 성공을 따로 집계한다. 같은 의미의 질문에 응답하지 못한 기록은 검색 개선의 평가 사례로 보존하며, 질문을 원문 표현으로 바꾸는 것으로 해결 완료 처리하지 않는다.
- 파일 종류는 확장자만으로 확정하지 않는다. 보관본의 영상·점군 메타데이터 미지원 상태와 STL 좌표 단위 미확정 상태를 실제 분석 완료로 승격하지 않는다.
- 숫자 문자열을 허용하는 필터만으로 근거 기반 설명을 보장하지 않는다. 같은 숫자라도 대상·시각·물리량이 틀린 경우를 시험한다.
- 옛 시간 검증 중 NaN 검사 누락, 재표본화의 시작 이전 질의 처리, 문자열 ID 순서에 의존한 시간 분할은 그대로 옮기지 않는다.
- 연구용 기준모형, 합성 시험, 실행 경로 확인, 현장 품질 모형은 각 상태로 남긴다. 채택되지 않은 학습 모델과 데이터 부족 기록도 보존한다.
- 외부 인증 시스템·데이터베이스·거대한 운영 규칙 묶음을 작은 로컬 제품에 통째로 추가하지 않는다. 필요한 기능의 연결부터 한다.
