# 입력 자료: 무엇을 읽었고 무엇을 가져왔는가

> 상태: 참고

이 저장소의 정본은 [ARCHITECTURE.md](../ARCHITECTURE.md)와 [CLAUDE.md](../CLAUDE.md)다. 옛 저장소와 대표 PC의 정본 문서 묶음은 **입력 자료**이며 이 저장소의 정본이 아니다.
공개 저장소이므로 입력 자료의 내용, 문서 ID, 경로, 회사 내부 자료, 출원 중인 특허 내용은 여기에 옮기지 않는다. 아래는 일반 원칙 수준으로 무엇을 가져왔는지만 적는다.

## 가져온 원칙

| 원칙 | 이 저장소에서 어디에 있는가 |
|---|---|
| 한 개념은 한 곳에서만 정의한다 | `config/authority.yaml`, `tests/test_authority.py` |
| 물리 값은 엔진에서만 나오고, LLM은 값을 만들지 않는다 | CLAUDE.md 규칙 7, 서비스 층은 팩의 답을 그대로 돌려준다 |
| 관측한 것, 계산한 것, 생성한 것을 구분한다 | 값의 지위 (PhysicsAnswer) |
| 검증 상태는 문서 상태나 엔진 성공과 다르다. 합성 결과를 검증된 것처럼 올리지 않는다 | `config/status.yaml`, `tests/test_control_tower.py`의 "검증 완료" 점검 |
| 같은 결과인지 알아볼 표식을 둔다 (내용 해시, 개정) | `PhysicsAnswer.revision_id()`, `Provenance` |
| 규칙은 문서에만 두지 않고 점검으로 지킨다 | 컨트롤타워 최소판 |
| 문서는 상태를 표시하고, 새 문서보다 기존 문서 수정이 먼저다 | 문서 상태 5종, CLAUDE.md 규칙 2 |
| 공용 계약은 한 곳에서만 바꾼다 | 결과 형식 변경은 별도 PR |

## 2026-11-24에 더 읽은 것

대표 PC의 방향 문서 새 판, 열 영역 알고리즘 개발 보고서(개정판), 보존 목록을 읽었다. 목록은 스스로 "통합 최종본 아님"이라고 적고 있다. 방향 문서의 세부 문서 네 개는 본문을 받지 못해 읽지 못했다.

| 구분 | 내용 | 자리 |
|---|---|---|
| 가져옴 | 관측 연산자, 보정 파라미터, 식별 가능성, 오차 예산 구조 | [로드맵](roadmap.md) 6절 |
| 가져옴 | 위험을 추정 분포에서 낸 초과 확률로 보고 | 같은 곳 |
| 가져옴 | 합성 정답 시험과 음성 대조를 실제 기준 대조와 구분 | 로드맵 1번 조건 |
| 가져옴 | 학습은 물리 값과의 편차만 맡고 범위 밖이면 물리 값으로 복귀, 시료·로트 단위 분할 | 로드맵 3번 조건 |
| 미룸 | 열화상 방사 관측, 데이터 동화, 세계 모형 | 열 영역을 열 때 |
| 미룸 | 물리 모형 전체 목록, 시각화 프로파일 묶음, 하나의 통합 화면 | 영역을 하나씩 여는 원칙 |
| 가져오지 않음 | 병렬 작업 소유권, 단계별 기간, 옛 저장소 이름과 내부 경로 | 단독 병합, 기간 미기재, 규칙 8 |

**제품 정의의 차이.** 방향 문서는 Studio를 AI와 물리를 만드는 개발 환경, Physics를 범용 해석 제품, Fab을 현장 적용 제품으로 적는다. 이 저장소의 정본은 ARCHITECTURE.md이며 대표가 2026-11-24에 정한 정의(Studio는 비전문가용, Physics는 전문가용, Fab은 자기 Fab을 꾸리는 곳)를 따른다.

## 아직 가져오지 않은 것

- 표시 상태(화면의 보기 설정)와 물리 값을 분리하는 규칙. 화면 쪽 코드가 더 생긴 뒤 규칙으로 만든다.
- 선행 단계, 단위, 불확실성이 없으면 계산하지 않는 "닫힘" 규칙. 지금은 영역별 입력 검사로만 있다.
- 병렬 개발에서 폴더 소유권을 나누는 규칙. 지금은 대표 한 명이 병합한다.

## 가져오지 않기로 한 것

- 11개 기술 층의 구조와 12개 에픽: 이 저장소는 7개 모듈(C1~C7)로 시작했다. 필요한 부분만 모듈에 대응시킨다.
- 옛 엔진 이름과 문서 체계: 이름이 아니라 필요한 일만 가져온다.
- 많은 워크플로와 보고서 문서: 옛 저장소가 불어난 원인이므로 점검 세 가지와 상태 파일 하나로 시작했다.

## 아직 정해지지 않은 것

대표 PC의 정본 문서 묶음은 스스로 "최종 아님"이라고 적고 있다. 어느 판을 기준으로 삼을지, 어떤 부분을 공개 저장소 문서로 옮길지는 대표가 정한다. 정하기 전에는 이 표만 늘린다.
