# ConT 생성형 AI 작업 흐름과 첫 완성본 인수

> 상태: 보조

2026-11-25 대표가 확정한 제품 방향을 개발 작업과 인수 증거로 풀어 쓴다. 제품 정의는 [ARCHITECTURE.md](../ARCHITECTURE.md), 실행 순서는 [roadmap.md](roadmap.md), 현재 구현 상태는 [config/status.yaml](../config/status.yaml)이 기준이다. 이 문서는 구현 완료 보고가 아니다.

## 현재 범위: 기존 모델로 소프트웨어 완성

[아키텍처의 개발 단계](../ARCHITECTURE.md)에 따라 이 문서의 인수 흐름을 기존 모델의 실제 추론으로 먼저 완성한다. PINN의 다양한 물리·숨은 물리·물리 잔차 자체 모형 SW는 학습 없이 병행하며, 대규모 현장 데이터 수집·라벨링·학습은 이 소프트웨어를 실제로 사용한 뒤 필요한 범위를 정한다. 샘플 입력, 사용자 파일, 구조 명세, 산출물 저장과 소프트웨어 시험은 지금 구현한다.

완료 판단에는 아래 여섯 기능과 첫 본딩 대화의 실제 화면 실행, 실제 생성 파일, 선택 수정 전후, 종료 후 복원을 함께 제시한다. 오류·취소·재시도도 확인한다. 단위 시험 통과나 더미 생성만으로 이 인수를 대신하지 않는다. 학습 성능이나 산업 예측 정확도를 이 소프트웨어 인수 조건으로 추가하지 않는다.

## 1. 여섯 핵심 기능의 완료 조건

| 핵심 | 구현할 연결 | 완료를 확인할 증거 |
|---|---|---|
| 실제 대화와 문맥 유지 | 실제 LLM에 프로젝트 상태·최근 대화·선택 결과를 전달하고 정정·지시 대상을 해석 | 10턴에서 조건·대상 유지, “두 번째”와 “방금 것” 해석, 두 사용자 격리, 실패한 변경의 미반영 |
| 작업 계획과 순차 실행 | 실제 LLM 계획을 검증하고 등록 도구를 의존 순서로 실행, 완료 결과부터 표시 | 계획·도구 인자·단계 이벤트·실제 출력 연결, 부분 실패·취소·중복 요청·재접속 시험 |
| 다양한 결과물 생성 | 설명·이미지·도식·그래프·3D·4D 도구를 작업 실행기에 등록 | 실제 이미지 파일, 데이터 기반 그래프, 렌더링 가능한 3D와 단계 시퀀스. 가짜 공급자는 별도 집계 |
| 선택한 결과 편집 | 영역·부품·그래프 계열·공정 단계를 식별하고 선택 범위와 변경 내용을 저장 | 수정 전후 버전, 선택 밖 구조의 보존, 이전 버전 복원, 관련 작업만 재실행한 로그 |
| 결과 간 일관성 | 대상·부품·조건·실행·버전·시간축을 명시적으로 참조 | 설명과 그래프 값 대조, 2D/3D 부품 대응, 같은 시간의 장면·커서, 오래된 결과 혼입 차단 |
| 작업 저장과 이어 하기 | 프로젝트·대화·생성물·부모 버전·선택·카메라·재생 상태와 계획 체크포인트 저장 | 프로세스 종료 후 재열기, 같은 산출물 해시와 선택 복원, 실패 단계 재개, 누락 파일 처리 |

10턴은 이 흐름의 시험 길이이며 정확도나 현장 성능을 보장하는 수치가 아니다. 실제 공급자는 같은 대화를 반복하고 성공·실패·소요시간·모델 버전을 기록한다. 제품 목표 수치는 첫 기준 측정 뒤 확정한다.

## 2. 첫 인수 대화: 하이브리드 본딩

| 순서 | 사용자 요청 | 화면과 저장 결과 | 확인할 것 |
|---|---|---|---|
| 1 | 하이브리드 본딩 과정을 설명해줘 | 설명과 단계 목록. 장비별로 달라지는 부분·입력 가정은 분리 | 다른 산업의 이전 결과를 새 답으로 쓰지 않음 |
| 2 | 구조 이미지를 만들어줘 | 실제 생성 모델의 이미지와 대응하는 구조 명세 | 사용 모델·입력·생성 파일·대상 ID 연결 |
| 3 | 층별 구조를 3D로 보여줘 | 같은 대상의 층·부품 ID와 이름을 가진 회전 가능한 장면 | 이미지와 부품 대응, 임의 치수가 실측으로 바뀌지 않음 |
| 4 | 접근·정렬·접촉 과정을 움직여줘 | 설명용 단계 4D, 재생·일시정지·탐색 | 접합 품질/온도/응력 계산이 없어도 설명용 동작 생성은 진행 |
| 5 | 두 번째 단계만 느리게 하고 회전해서 보여줘 | 정렬 단계 재생 구간과 카메라 경로만 새 버전으로 수정 | 다른 단계·부품·조건 보존. 화면 2D 회전이 아닌 실제 3D 카메라 변경 |
| 6 | 이전 것과 비교하고 이 프로젝트를 저장해줘 | 이전/수정 버전 비교, 프로젝트 저장 | 원본 유지, 변경 영향 목록, 선택 결과와 카메라 상태 저장 |
| 7 | 종료 후 이 프로젝트를 이어서 열어줘 | 대화·설정·결과·선택·재생 위치 복원 | 모델 재호출 없이 저장 산출물을 먼저 재현; 누락은 명시 |

설명 이미지에서 정확한 3D CAD가 자동 복원된다고 가정하지 않는다. 첫 버전은 공통 구조 명세와 매개변수 기반 장면 템플릿으로 대상·층·부품 대응을 유지한다. 표현이 어긋나면 검수·수정 대상으로 표시한다. 정밀 CAD, 물리장, 접합 품질은 별도 엔진과 데이터의 지원 범위에 따른다.

## 3. 기존 모듈에 연결하는 개발 단위

| 작업 | 재사용할 곳 | 추가할 것 |
|---|---|---|
| 실제 대화에서 계획 생성 | `cont.llm`, `dialogue.context`, `dialogue.plan` | 선택 결과를 포함한 문맥, 실제 공급자 계획 출력, 도구 인자 검증 |
| 순차 결과 표시 | `dialogue.plan`, `plan_store`, 서비스·화면 | 작업 ID/단계 이벤트 전달, 대기·실행·완료·실패·취소 표시 |
| 이미지 생성·편집 | `cont.generation` | diffusers 어댑터의 실제 생성 인수, 참조 이미지·영역 선택·편집, 부모 산출물 연결 |
| 그래프·3D·4D | `cont.view`, `cont.shape` | 검증 가능한 그래프·장면 사양, 본딩 층별 템플릿, 단계와 카메라 트랙 |
| 입력 이해 | `cont.signal`, `cont.shape`, `service.ledger` | 업로드 원본 등록, 표·도면 추출, 원본 위치와 추출값 확인·수정 |
| 선택 수정·일관성 | 실행 기록과 형상·결과 ID | 의존 관계와 변경 영향, 변경 결과의 새 버전, 이전 결과의 오래됨 표시 |
| 저장·재개 | `service.runs`, `service.ledger`, `dialogue.plan_store`, Fab 구성 | 프로젝트/사용자별 대화·산출물 목록·선택·카메라·재생 상태 복원 |

새 프로젝트 계약은 구현 전에 ARCHITECTURE.md의 기존 계약과 대조한다. `Quantity`, `PhysicsAnswer`, 실행 기록, 자료 장부를 중복 정의하지 않는다. 위 연결 중 상당수는 미구현이며 기존 모듈의 존재가 제품 통합의 완료를 뜻하지 않는다.

## 4. 같은 대상과 선택 편집의 규칙

대상·부품·입력 조건·산출물·부모 버전·실행·자료 참조·시간축·선택 범위를 연결한다. 기존 식별자가 있는 경우 재사용하고 부족한 계약만 추가한다.

- 카메라만 변경: 장면의 표시 상태를 수정하고 계산·이미지 모델을 불필요하게 다시 호출하지 않는다.
- 정렬 단계만 느리게: 설명용 재생 매핑을 수정한다. 측정 시간이나 계산된 물리 값은 바꾸지 않는다.
- 부품 길이 변경: 형상과 그 치수를 참조하는 도식·계산·설명만 갱신한다. 영향을 받지만 아직 갱신하지 못한 결과는 이전 상태로 표시한다.
- 이미지 부분 수정: 마스크 또는 대상 참조와 부모 이미지를 보존한다. 생성 모델의 선택 밖 변경은 구조/시각 검수로 확인하고 보존했다고 무조건 단정하지 않는다.
- 모든 결과를 같은 최신 버전으로 덮어쓰지 않는다. 비교 중인 이전 실행은 고정하고 최신 결과로 전환할 때 연결을 명시한다.

## 5. 실제 생성, 설명용 4D, 물리 결과

| 종류 | 가능한 작업 | 근거 |
|---|---|---|
| 설명문·설명 이미지 | 사용자 의도에 맞는 설명과 시각화 | 입력·참조 자료·생성 모델 기록 |
| 도식·그래프 | 구조 명세, 사용자 입력, 계산·측정 데이터를 정확히 표시 | 원본 값·단위·대상·버전 |
| 설명용 4D | 공정 단계, 이동·정렬·접촉의 구성, 카메라·재생 편집 | 장면과 단계 명세. 임의 재생시간은 물리 시간과 구분 |
| 물리장·예측 4D | 온도·응력·변형·운동 결과의 시간 표현 | 해당 풀이기 또는 측정값, 적용 범위·시간축·검증 상태 |

생성 이미지의 색을 물리 수치처럼 읽거나 설명 동작의 접촉을 실제 접합 성공으로 해석하지 않는다. 단순 시점 회전과 단계 애니메이션도 사용자가 수정할 수 있는 제품 기능이며, 고정 영상을 재생한 것만으로 편집 가능한 4D 완료를 보고하지 않는다.

PINN의 계산·역추정·잔차 결과는 같은 대상·조건·버전·시간축을 참조해 그래프·3D·4D에 연결한다. 방정식 잔차와 관측-모델 차이는 별도 항목으로 표시한다. PINN 작업의 대기·실패는 설명·이미지·기본 장면 생성을 막지 않으며, 관측 없는 내부장 계산을 실측 기반 복원으로 표시하지 않는다. 이 연결은 병행 개발 목표이며 현재 완료를 선언하지 않는다.

## 6. 완료보고와 확장

한 작업의 보고에는 코드 커밋, 실제 공급자/모델, 입력, 생성 파일, 실행 로그, 화면 인수 결과, 저장 복원 결과, 남은 실패를 적는다. 문서 작성·단위 시험·실제 생성·전체 작업 성공을 분리한다.

첫 본딩 흐름 뒤 같은 코어를 체결·관절의 설명과 구조·동작 편집에 적용한다. 확장 때 새 도구와 템플릿의 양, 재사용한 계약, 수정 성공률, 완료시간을 기록한다. M05~M09의 예측·진단 정확도는 해당 전문 기능을 연결할 때 독립적으로 평가한다.
