# 통합 작업(GF) 증거 정리 (2026-11-27)

> 상태: 기록

PR #98~#113에서 한 작업이 [integration_jobs.yaml](integration_jobs.yaml)의 생성형 통합 작업(GF01~GF14)에 **어느 인수 항목까지 증거가 있는지**를 정리한 기록이다. 기준은 [integration_control_plan.md](integration_control_plan.md)의 인수 항목과 증거 기준이다.

- 이 문서는 작업 상태 전환(`planned → ready → …`)이 아니다. YAML의 `planning_state: planned`와 `owner` 미지정은 그대로이고 담당 배정·검토 기록도 없다. 아래 "있음"은 코드와 시험의 증거이지 인수(`accepted`) 판정이 아니다.
- 계획 문서의 변경은 기능 구현 완료로 세지 않았다. 문서만 바뀐 PR(#99, #101, #103, #107)은 표에서 제외했다.
- 기준 커밋은 `main` `02d94a8`(PR #113 병합)이다. 실제 모델 결과는 모델·환경과 함께 적었고 한 번의 측정을 일반화하지 않았다.

## 3. 증거 묶음 기준과의 차이

[통제 계획](integration_control_plan.md)의 증거 묶음(검사한 커밋·입력 개정·환경·공급자·실행 명령·파일 해시·남은 문제·검토)에 비추어 부족한 점이다.

- **실행 결과 파일이 저장소 밖에 있다.** 로컬 모델 측정의 원본 JSON 보고서와 SDXL 출력 이미지는 대표 PC의 작업 폴더에만 있고 해시를 문서에 남기지 않았다. 문서에는 요약 수치만 있다.
- **환경 기록이 일부뿐이다.** GPU와 VRAM, 모델 이름은 있으나 OS·Python·의존성 버전·검사한 커밋을 한 곳에 묶어 남기지 않았다. 측정에 쓴 커밋은 PR 병합 커밋으로 추적할 수 있다.
- **검토 기록이 없다.** 담당 외 검토 역할의 확인은 없고, 병합은 CLAUDE.md의 대표 단독 병합 규칙에 따랐다.
- **필수 시험의 건너뜀:** 브라우저 시험은 Chrome이 있는 환경에서만 돌고 없으면 건너뛴다. 건너뜀을 통과로 세지 않았다.
- **측정의 한계:** 계획 품질 사례는 모두 직접 쓴 것이라 저자 편향이 있고, 같은 조건에서도 서버 캐시 상태에 따라 결과가 흔들렸다. 두 모델은 사례별로 거의 같은 결과를 냈다.

## 4. 연결이 가장 비어 있는 곳

증거의 공백은 아래 순서로 크다. 이것은 작업 지시가 아니라 정리이며 순서는 대표가 정한다.

1. **화면:** 대화·3D 장면·저장을 한 웹 화면에서 쓰는 흐름이 없다(GF04·GF07·GF08·GF11의 화면 인수 항목 전부). 장면 페이지와 대화·저장은 각각 시험됐지만 이어져 있지 않다.
2. **3D 장면 직접 선택**(GF08): 클릭 선택은 구현됐으나(`s4d:select`, `select_from_screen`) 한 화면에서 세션과 이어져 있지 않다.
3. **실제 이미지 모델의 기본 연결과 그림 검수**(GF05): 지금 기본은 가짜 생성기이고 FLUX.2 klein·Qwen-Image 비교는 아직이다.
4. **그래프·이미지 편집·입력 이해·사용자 분리·사례 재사용**(GF06·GF09·GF12·GF13·GF14): 이번 작업 범위에서 하지 않았다.
