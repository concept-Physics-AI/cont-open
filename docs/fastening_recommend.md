# 체결 팩: 설계 추천

> 상태: 보조

안전율 목표를 주면, 그 목표를 만족하는 규격·강도 등급·조임 토크의 조합을 찾아 제안한다 (체결 슬라이스 4).

## 쓰는 법

체결 서버(`python -m cont.dialogue.serve_fastening`)에서 말로:

```
항복 안전율 1.5 이상, 미끄럼 안전율 2.5 이상이 되게 해 줘
  → 1번, 2번, 3번 추천 (바꾸지는 않는다)
1번으로
  → 그 추천을 적용하고 다시 계산
```

코드에서:

```python
from cont.packs.fastening.recommend import recommend

rec = recommend(joint, load, {"safety_yield": 1.5, "safety_slip": 2.5})
rec.candidates[0].changes      # {"size": "M16", "tightening_torque": 112.5}
rec.answer                     # 공통 결과 형식 (PhysicsAnswer)
```

목표로 쓸 수 있는 것: 항복(`safety_yield`), 벌어짐(`safety_opening`), 미끄럼(`safety_slip`), 면압(`safety_pressure_head`, `safety_pressure_nut`), 피로(`safety_fatigue`) 안전율.

## 찾는 방법

1. 표준 데이터에 있는 규격(M6~M24)과 강도 등급(8.8, 10.9, 12.9)을 모두 놓는다.
2. 조합마다 조임 토크를 0부터 "조임 중 항복에 이르는 토크"까지 훑어, 모든 목표를 만족하는 토크 범위를 찾는다. 범위의 끝은 이분법으로 좁힌다.
3. 그 범위 안에서 지금 토크에 가장 가까운 값을 0.5 N·m 단위로 잡는다.
4. **지금 설계에서 가장 적게 바꾸는 순서**로 늘어놓는다: 토크만 → 강도 등급까지 → 규격까지. 규격은 가까운 것부터.

계산은 체결 팩의 VDI 2230 식을 그대로 쓴다. 추천을 위한 새 식이 없다.

## 지키는 원칙

- **추천은 제안이다.** 추천을 받는 것만으로는 조인트가 바뀌지 않는다. "1번으로"처럼 골라야 바뀐다.
- **목표 값은 묻는 사람이 준다.** 코드가 "안전율은 얼마여야 한다"를 정하지 않는다. 합격·불합격 판정이 아니다.
- **순서의 뜻을 숨기지 않는다.** 바꾸는 양이 적은 순서일 뿐, 비용·무게·조달로 고른 순서가 아니다. 그 기준은 아직 정하지 않았다.
- 목표가 아닌 안전율도 함께 보인다. 항복 안전율을 올리려고 토크를 낮추면 미끄럼 안전율이 내려가는 것처럼, 맞바꿈이 보여야 한다.
- 만족하는 조합이 없으면 없다고 말한다. 계산할 수 없는 목표(축직각 하중이 없는데 미끄럼 안전율)는 무엇이 필요한지 말한다.
- LLM을 쓰면 LLM은 목표(`targets`)나 고른 번호(`choose`)만 JSON으로 답한다. 허용한 키와 형식이 아니면 버리고 규칙으로 읽는다.

## 아직 없는 것

- 판 두께, 바깥지름, 볼트 수 같은 다른 설계 변수를 바꾸는 추천. 지금은 규격·등급·토크만 바꾼다
- 비용·무게·조달 가능성을 따진 순위
- "가능한 한 작은 볼트로"처럼 목표가 아니라 방향을 주는 요청
- 여러 하중 조건을 함께 만족하는 추천
- 표준 데이터에 없는 규격(M5, M14, M30 등)과 등급, 가는나사

## 신뢰도

"중간"이다. 계산식은 체결 팩과 같고, 추천된 조합이 실제로 목표를 만족하는지와 토크 범위의 양 끝이 맞는지는 테스트로 확인한다.
표준 예제·FEM 기준값과의 대조(슬라이스 2)는 아직 하지 않았다.
