# ConT Fab: 고르기

ConT Fab은 물리 정보(2D · 3D · 4D)를 쇼핑하듯 골라 담아 자기 현장의 Physical AI를 꾸리는 곳이다 ([ARCHITECTURE.md](../ARCHITECTURE.md)의 "3제품 1코어").
그 첫 부분인 **고르는 곳**을 만들었다. 꾸리는 곳, 시나리오, 공장 화면은 아직 없다.

## 무엇이 있는가

| 것 | 내용 | 자리 |
|---|---|---|
| 목록 | 고를 수 있는 물리 정보. 지금 코드에 실제로 있는 엔진만 적는다 | `config/fab/catalog.yaml` |
| 미리보기 | 항목마다 엔진을 예제 값으로 돌린 결과 (그림이나 값). 손으로 그린 그림이 아니다 | `src/cont/fab/previews.py` |
| 고르기 화면 | 상품 카드, 찾기, 형태·물리 영역으로 거르기, 바구니, 고른 것 내려받기 | `src/cont/fab/store.py` |
| 고른 것 | `my-fab.json` (형식 `cont-fab-selection`). 꾸리기 화면의 출발점이 될 파일 | `src/cont/fab/catalog.py`의 `selection` |

## 규칙

- **없는 것을 싣지 않는다.** 목록의 항목은 모두 미리보기 함수를 가져야 하고, 그 함수는 엔진을 실제로 돌린다. 시험이 이것을 확인한다.
- **가격을 적지 않는다.** 그 자리에 "넣는 것"(쓰려면 필요한 입력)과 "내는 것"을 적는다.
- **값의 지위를 적는다.** 모든 카드에 "계산값 · 검증 전"이 붙는다. 가상 데이터로 돌린 것은 "가상 데이터"라고 적는다.
- 바구니는 화면 안에서만 담긴다. 서버에 저장하지 않는다.

## 항목을 더하려면

1. 엔진을 만든다 (물리 팩 등).
2. `src/cont/fab/previews.py`에 그 엔진을 예제 값으로 돌리는 함수를 더한다.
3. `config/fab/catalog.yaml`에 항목을 적는다 (`preview`에 그 함수 이름).

## 쓰는 법

```
python -m cont.fab.store --out fab.html
```

## 아직 없는 것

- 내 Fab 꾸리기: 설비 사진·3D를 올리고 그 위에 고른 것을 얹기, 현장 신호 잇기.
- 시나리오: 조건을 바꿔 여러 경우를 돌리고 판단을 기록하기.
- 꾸린 것으로 공장 화면 만들어 내기. 지금 있는 예는 손으로 만든 설비 이상진단 화면 하나다 ([diagnosis_screen.md](diagnosis_screen.md)).
- 상품을 눌러 자세히 보기, Studio · Physics에서 가져오기.
