# ConT Fab: 고르기

> 상태: 보조

## 현재 제품 흐름에서의 역할 (2026-11-25)

Fab은 [핵심 생성·편집 흐름](generative_workflow.md)에서 만든 결과를 선택·배치·재사용하고 저장해 이어 가는 제품이다. Studio·Physics와 대상·조건·산출물 버전을 공유하는 통합이 다음 목표이며 아직 완성되지 않았다. 전문 진단 모델이나 현장 연결 없이도 설명 이미지·그래프·3D·4D 구성의 사용자 흐름부터 개발한다.

ConT Fab은 물리 정보(2D · 3D · 4D)를 쇼핑하듯 골라 담아 자기 현장의 Physical AI를 꾸리는 곳이다 ([ARCHITECTURE.md](../ARCHITECTURE.md)의 "3제품 1코어").
**고르는 곳**과 기본 **구성기**(조건·크기·순서 설정, 브라우저 저장과 파일 재열기)를 만들었다. 현장 신호 읽기, 시나리오, 공장 화면은 아직 없다. 서버의 실행 저장소를 켜면 실행 ID 복원 경로가 있으나 실제 브라우저 인수와 Studio 프로젝트 통합은 아직이다.

## 무엇이 있는가

| 것 | 내용 | 자리 |
|---|---|---|
| 목록 | 상품(엔진), 형태, 물리 영역, 쓰임, 세트, 샘플을 만들 조건 | `config/fab/catalog.yaml` |
| 샘플 | 상품마다 엔진을 조건별로 돌린 결과. 손으로 그린 그림이 아니다 | `src/cont/fab/previews.py` |
| 3D 그림 | 형상의 삼각형을 그림 한 장(SVG)으로. 카드에 3D를 여러 장 늘어놓을 때 쓴다 | `src/cont/view/iso_svg.py` |
| 고르기 화면 | 진열대, 자세히 보기, 견주기, 내 Fab 띠 | `src/cont/fab/store.py` |
| 고른 것 | `my-fab.json` (형식 `cont-fab-selection`). 꾸리기 화면의 출발점이 될 파일 | `catalog.selection` |

## 묶는 방법

| 겹 | 값 |
|---|---|
| 형태 | 이미지, 그래프, 3D, 4D, 영상, 신호, 계산값, 판단 · 점검 |
| 물리 특성 | 형상, 응력 · 압력, 변형 · 변위, 힘 · 체결력, 전류 · 진동, 압력 · 유량, 온도, 시간 · 사이클, 품질 치수, 계측, 점검 |
| 물리 영역 | 체결, 절삭, 프레스, 압출, 설비 공통 |
| 쓰임 | 설계할 때, 조건 잡을 때, 감시할 때, 점검할 때, 보고할 때 |
| 세트 | 한 번에 담는 묶음 (체결 공정, 응력 한눈에, 설비 감시, 절삭 설비) |

## 상품과 샘플

상품 하나 = 엔진 하나. 샘플 = 그 엔진을 어떤 조건으로 돌린 결과. 목록의 `samples`에 조건(규격, 재료, 이송 등)을 적으면 그만큼 샘플이 만들어진다.
규격별 샘플의 조임 토크는 사람이 적지 않는다. 추천 엔진이 목록의 예시 목표(`sample_rule.yield_safety`)를 만족하는 토크를 고른다.

## 화면

- **맨 위 한 장**: 조이는 과정의 장면이 차례로 바뀐다 (엔진이 만든 장면). 움직임을 줄이도록 설정한 기기에서는 멈춰 있다.
- **진열대**: 세트 한 줄, 그리고 형태마다 한 줄. "물리 특성별"을 누르면 물리 특성마다 한 줄로 다시 묶인다. 옆으로 밀어 본다.
- **카드 하나 = 상품 하나.** 같은 상품에서 수치만 다른 것은 카드를 늘리지 않고, 카드의 조건 단추(M8, M10, …)를 눌러 그 자리에서 바꿔 본다. 서로 다른 카드는 서로 다른 물리다 (예: 축 방향 응력, 등가응력, 전단 응력, 변위).
- **거르기**: 찾는 말, 형태, 쓰임. 물리 영역은 접어 두었다.
- **자세히 보기**: 카드의 그림을 누르면 크게 보고, 샘플을 넘겨 보고, 넣는 것 · 내는 것 · 쓰임 · 한계 · 함께 담으면 좋은 것을 본다.
- **그 자리에서 다시 만들기**: 서버로 띄웠을 때, 규격과 조임 토크를 바꾸면 엔진이 다시 계산해 새 샘플을 낸다 (체결 상품). 파일로 낸 화면에서는 미리 만든 샘플만 본다.
- **견주기**: 샘플 셋까지 나란히.
- **내 Fab 띠**: 담은 것이 아래에 늘 보인다. 현장 이름을 적고 파일로 내려받는다.

## 규칙

- **없는 것을 싣지 않는다.** 상품은 엔진을 실제로 돌리는 샘플 함수를 가져야 하고, 샘플이 하나도 안 나오면 목록을 만들지 못한다. 시험이 확인한다.
- **가격을 적지 않는다.** 그 자리에 "넣는 것"과 "내는 것"을 적는다.
- **값의 지위를 적는다.** "계산값 · 검증 전". 가상 데이터로 돌린 것은 "가상 설비", "가상 데이터"라고 적는다.
- 바구니는 화면 안에서만 담긴다. 서버에 저장하지 않는다.

## 항목을 더하려면

1. 엔진을 만든다 (물리 팩 등).
2. `src/cont/fab/previews.py`에 그 엔진을 조건마다 돌려 샘플들을 내는 함수를 더한다.
3. `config/fab/catalog.yaml`에 항목을 적는다 (`preview`에 그 함수 이름).

## 쓰는 법

```
python -m cont.fab.store                 # 브라우저에서 http://127.0.0.1:8768 (조건을 바꿔 다시 만들 수 있다)
python -m cont.fab.store --out fab.html  # 파일 하나로
```

## 아직 없는 것

- 내 Fab 꾸리기의 나머지: 설비 사진·3D를 올리고 그 위에 고른 것을 얹기, 현장 신호를 실제로 읽어 잇기 (조건·크기·순서 설정과 저장은 아래 "내 FAB 구성"에 있다).
- 시나리오: 조건을 바꿔 여러 경우를 돌리고 판단을 기록하기.
- 꾸린 것으로 공장 화면 만들어 내기. 지금 있는 예는 손으로 만든 설비 이상진단 화면 하나다 ([diagnosis_screen.md](diagnosis_screen.md)).
- 현장의 사진이나 3D를 올리면 거기에 맞는 것을 내주는 일. 
- Studio · Physics에서 가져오기. 체결 밖의 상품은 그 자리에서 다시 만들기가 안 된다.

## 카드와 상세 창의 역할

- 카드: 미리보기 그림, 한 줄 설명(`short`, 24자 이하), 조건 단추, 핵심 숫자 하나, 견주기·담기. 카드 어디를 눌러도 상세 창이 열립니다.
- 상세 창: 긴 설명, 조건별 숫자 전부, 넣는 것·내는 것·이럴 때·알아둘 점, 함께 담으면 좋은 것, 다시 만들기.

## 그림의 품질

- 분포 그림은 칸 모양 사각형이 아니라, 물리장을 부드럽게 이어 한 장의 PNG로 그려 SVG 안에 넣습니다. 칸이 없는 곳(볼트 자리)은 투명합니다. 값은 엔진이 낸 물리장 그대로이고, 사이를 이은 것은 보기 좋게 하기 위한 보간입니다.
- 카드에서는 그림 영역만 보이게 잘라 보여 주고(`data-card`), 범례·상태 문구는 상세 창에서 읽습니다.
- 카드를 누르면 그 자리에서 상세 창이 커지고, 닫으면 카드로 줄어듭니다. 움직임 줄이기 설정에서는 효과를 끕니다.

## 내 FAB 구성: 고르기 → 조건 → 담기 → 배치·연결 → 저장·다시 열기

| 단계 | 하는 일 | 보존되는 것 |
|---|---|---|
| 미리보기 | 카드를 눌러 상세 창을 연다. 형태마다 다른 조작이 있다 | 3D: 시점·확대·보이는 부품 / 4D·영상: 재생 단계 / 계산값: 입력(서버에서 다시 계산) / 판단·점검: 근거 목록 |
| 조건 설정 | 카드의 규격 단추, 상세 창의 조건 | 조건 이름과 params (규격·조임 토크) |
| 담기 | "이 조건으로 내 FAB에 담기". 같은 상품을 다른 조건으로 또 담을 수 있다 | 위의 조건과 보던 설정 그대로 |
| 배치·연결 | 구성 화면에서 크기(S·M·L), 순서, 조건, 데이터 연결 | 칸 크기·순서, 데이터 출처(엔진 계산값/현장 신호 이름)와 메모 |
| 저장·다시 열기 | 저장(브라우저), 내려받기·파일 열기(my-fab.json) | `cont-fab-selection` 버전 2. 버전 1(이름만 담긴 것)도 열린다 |

- **현장 신호 연결은 기록만 합니다.** 신호 이름을 적어 두는 것이고, 실제로 신호를 읽어 오는 기능은 아직 없습니다. 칸에도 그렇게 적힙니다.
- 공개 정적 화면에서는 준비된 조건만 고를 수 있습니다. "다시 만들기"는 서버 실행 환경에서만 됩니다.
- 3D 돌려 보기는 규격별 삼각형 자료(소수 첫째 자리까지)를 화면에 싣고 브라우저에서 그립니다. 값을 새로 계산하지 않습니다.
- 영상 카드의 재생은 장면 네 장을 순서대로 보여 주는 것입니다. 영상 파일은 체결 화면에서 만듭니다.
- 저장한 조건이 목록에 없으면(서버에서 다시 만든 조건 등) 첫 조건의 그림을 보이고 그렇다고 칸에 적습니다.
- 아직 없는 것: 산업군 필터(분류 기준 필요), 현장 사진 올리기, 칸을 끌어서 옮기기, 구성 결과를 운영 화면으로 여는 것.

## 표현 유형 (엔진 없는 것 중심)

진열대의 중심은 "아직 엔진이 없는 표현 유형"이다. 엔진이 이미 있는 것은 맨 아래 접힌 "지금 되는 것 (체결 사례)"에 둔다.

| 항목 | 내용 |
|---|---|
| 정의 | `config/fab/types.yaml` — 59개 유형(사용자 표 48 + 계산값 6 + 판단·점검 5), 엔진 목록(`engines`) 포함 |
| 엔진 없음 | 40개. 점선 카드 "준비 중 · 엔진 없음", 개념도(선 그림) + 결과 이름 + 바꿀 수 있는 것 + 필요한 엔진 |
| 지금 되는 것 | 19개는 `covered_by`로 기존 상품에 연결(체결 사례만). 준비 중 카드로 보이지 않음 |
| 그림 | `cont.fab.sketches` 코드가 그린 개념도. "예시 그림 · 실제 결과 아님" 표기. 실제 사진·결과 그림은 자리만 비워 둠 |
| 필요해요 | 담기가 아니라 요청. 내 FAB의 "엔진 필요 목록"에 쌓이고 `my-fab.json`의 `requests`(kind `engine_request`)로 저장·다시 열기 |
| 지키는 것 | 유형 카드는 결과처럼 보이는 그림·숫자를 만들지 않는다. 사진 겹침은 실측 지점과 계산 영역을 구분하고, 4D는 재생 기준을 적는다 |
