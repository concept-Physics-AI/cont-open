# 장기 개발 과제 (순서와 전제)

> 상태: 보조

2026-11-24에 대표가 아래 7개를 모두 진행하기로 했다. 이 문서는 **기간이 아니라 순서와 전제**만 적는다. 모듈 경계는 ARCHITECTURE.md가 먼저이며, 과제마다 브랜치 하나, PR 하나로 진행한다 (규칙 3). 현재 상태의 기준은 `config/status.yaml`이다.

## 한눈에

| 순위 | 과제 | 지금 상태 | 막고 있는 것 | 데이터 없이 할 수 있는 첫 일 |
|---|---|---|---|---|
| 1 | 검증 (C6)과 실측 대조 | 틀만 있고 기준 사례가 비어 있다. 결과는 모두 "검증 전" | 기준 자료 (표준 예제, 해석 기준값, 실측값) | 기준 자료 받는 형식을 정하고, 들어오면 바로 편차를 보고하게 해 둔다 |
| 2 | 물리 영역 확장 | 대화는 체결 하나. 가공과 진단은 뼈대 | 영역마다 기준 자료와 해석식의 한계 | 가공 영역의 한계와 필요한 자료 목록을 적는다 |
| 3 | 학습 (C7)과 학습된 모형 | 시작하지 않음 | 1번 (검증 없이 학습하지 않는다) | 시작하지 않는다 |
| 4 | Fab: 꾸리는 곳, 시나리오, 공장 화면 | 고르는 곳만 있다 | 무엇을 "꾸린다"고 할지 대표 결정 | 설비 이상진단 화면을 만든 과정에서 공통 부분을 뽑는 설계 |
| 5 | Physics: 전문가 작업 도구 | 체결 작업대 하나 | 외부 해석 도구 결과의 형식과 권리 확인 | 체결 작업대를 해석 설계자가 써 보고 고칠 점을 모은다 |
| 6 | 서비스 외부 공개와 운영 | 로컬 전용, 인증 없음, 저장 없음 | 서버 접근 설정 정리 (포트와 접근 소스), 공개 범위 결정 | 서버 보안 점검 순서와 배포 구조 설계 |
| 7 | 형상 (C5) 확장 | 볼트 조인트 하나 | CAD 엔진 실행 환경 (Docker로 정함) | 형상 명세를 영역별로 일반화하는 설계 |

## 앞뒤 관계

- 1번이 3번과 5번 (소재)의 전제다. 검증하지 않은 값으로 학습하면 믿을 수 없는 값이 늘어난다.
- 2번은 Studio와 Physics 모두에 쓰이므로 1번과 함께 간다.
- 6번 중 서버의 열린 포트 정리는 공개 여부와 관계없이 먼저 한다.

## 1번에 필요한 기준 자료

| 종류 | 내용 | 비고 |
|---|---|---|
| 표준 예제 | 표준 문서에 실린 계산 예제의 입력과 정답 | 출처 없는 사례는 받지 않는다 |
| 해석 기준값 | 같은 조인트를 해석 도구로 풀어 얻은 체결력과 응력 | 도구와 버전, 입력 조건을 함께 적는다 |
| 실측값 | 볼트 늘어남(여러 번), 조임 토크, 실제 체결력, 측정 도구와 불확도 | CSV 한 파일, 한 줄이 한 번의 측정 |

허용 오차는 정하지 않았으므로 (규칙 6) 처음에는 편차만 보고하고 판정하지 않는다.

## 대표 결정이 필요한 것

1. 기준 자료를 어디서 구할지 (위 세 종류 중 가진 것)
2. 다음에 열 물리 영역 (가공을 권장하나 기준 자료가 필요하다)
3. 서비스를 누구에게 어떻게 공개할지, 서버를 cont-open에 쓸지
4. Fab에서 "꾸리는 곳"의 범위
