# 개발 로드맵

> 상태: 정본

무엇을 어떤 순서로 만들고, 무엇이 끝나야 다음으로 가는지를 정한다. **기간은 적지 않는다.** 순서와 전제와 끝났다고 말할 조건만 적는다. 구조는 ARCHITECTURE.md, 규칙은 CLAUDE.md가 먼저이며, 현재 상태의 기준은 `config/status.yaml`이다. 이 문서와 어긋나면 상태 파일이 현재 사실이고, 이 문서를 고친다.

## 1. 목표

| 제품 | 쓰는 사람 | 목표 |
|---|---|---|
| Studio | 물리를 모르는 AI 전문가와 일반인 | 현실의 물리를 근거로 정확하고 현실과 이어진 답을 주는 생성형 AI. 물리 영역을 가리지 않는다 |
| Physics | 해석 도구를 쓰는 설계자, 3D CAD 설계자, 소재 전공자 | 물리·설계·소재는 아는 전문가가 AI를 쉽게 쓰게 돕는 소프트웨어 |
| Fab | 자기 Physical AI를 갖고 싶은 사람과 조직 | 각자의 Physical AI와 자기 Fab을 쉽게 만들게 돕는다 |

세 제품은 같은 코어(엔진과 서비스)를 쓴다. 값은 엔진만 낸다.

## 2. 지킬 원칙

1. 검증하지 않은 값은 "검증 전"이라고 적는다. 기준 자료가 생기기 전에는 허용 오차를 정하지 않고 편차만 보고한다.
2. 검증 없이 학습하지 않는다. 학습한 모형은 물리가 정한 한계 안에서만 쓴다.
3. 과제 하나는 브랜치 하나, PR 하나다. 구조를 바꾸면 ARCHITECTURE.md를 먼저 고친다.
4. 데이터가 없으면 있는 것처럼 만들지 않는다. 합성 데이터는 합성이라고 적는다.
5. 외부에 열 때는 보안을 먼저 정한다. 인증 없는 서비스는 이 컴퓨터에서만 연다.

## 3. 지금까지 한 것

| 영역 | 끝난 것 | 한계 |
|---|---|---|
| 구조와 규칙 | 3제품 1코어, 책임 모듈 표, 컨트롤타워 최소판(점검 테스트, 상태 파일, PR 양식) | |
| 코어 | 공통 결과 형식(값의 지위, 근거, 불확실성, 검증 상태, 개정 ID), 체결 해석, 절삭 뼈대, 설비 진단, 신호 분석 | 해석식과 수치해석만 있고 학습 모형은 없다 |
| 서비스 | 팩 목록, 계산 호출, 추가 동작(추정, 설계 추천) | 이 컴퓨터에서만 열리고 인증과 저장이 없다 |
| Studio | 체결 대화 화면, 다른 영역은 알아보고 아직 대화가 없다고 알림 | 대화는 체결 하나 |
| Physics | 체결 작업대 (추정, 설계 후보, 내보내기) | 합성 관측 예시, 실측 대조 없음 |
| Fab | 고르는 곳, 설비 이상진단 화면 한 예 | 꾸리는 곳과 시나리오 없음 |

## 4. 과제와 끝났다고 말할 조건

| 순위 | 과제 | 전제 | 끝났다고 말할 조건 |
|---|---|---|---|
| 1 | 검증(C6)과 실측 대조 | 기준 자료: 표준 예제, 해석 기준값, 실측값 (출처가 있는 것만) | 기준 사례가 `config/reference/`에 들어가고, 계산 결과와의 편차가 사례별로 보고된다. 허용 오차는 이 시점에 프로파일로 따로 정한다. 합성 자료로 한 시험(합성 정답 복원, 잘못된 값을 넣으면 잔차가 커지는지 보는 음성 대조)은 이 조건을 채우지 않으며 따로 표시한다 |
| 2 | 물리 영역 확장 | 영역마다 기준 자료와 해석식의 한계 | 두 번째 영역이 Studio 대화에서 답하고, 그 영역의 한계와 검증 상태가 답에 나온다 |
| 3 | 학습(C7)과 학습된 모형 | 1번의 기준 사례 | 학습 근거(데이터, 물리 교사)가 기록되고, 적용 범위 밖에서는 쓰지 않는 장치가 있다. 학습은 물리 값과의 편차만 맡고, 범위 밖이면 물리 값으로 돌아간다. 학습과 검증 자료는 시료·로트 단위로 나누며 행을 무작위로 나누지 않는다 |
| 4 | Fab: 꾸리는 곳, 시나리오, 공장 화면 | "꾸린다"의 범위를 대표가 정함 | 사용자가 고른 물리 정보로 자기 화면 한 개를 만들어 낸다 |
| 5 | Physics: 전문가 작업 도구 | 해석 설계자 사용 후 고칠 점, 외부 해석 결과의 형식과 권리 확인 | 해석 설계자가 자기 해석 한 건을 가져와 같은 화면에서 본다 |
| 6 | 서비스 외부 공개와 운영 | 서버 접근 설정 정리, 공개 범위 결정 | 인증, 사용자 구분, 결과와 개정 저장, 속도 제한, 감사 기록이 있고 지정한 사람이 외부에서 쓴다 |
| 7 | 형상(C5) 확장 | CAD 엔진 실행 환경(Docker) | 볼트 조인트 밖의 형상 하나가 명세에서 파일까지 나온다 |

## 5. 앞뒤 관계

- 1번이 3번과 5번의 소재 부분의 전제다.
- 2번은 Studio와 Physics가 함께 쓰므로 1번과 같이 간다.
- 6번 가운데 서버의 열린 포트 정리는 공개 여부와 관계없이 먼저 한다.
- 3번은 1번이 끝나기 전에는 시작하지 않는다.

**순서 조정 (2026-11-24 대표 결정): 쓸 수 있는 소프트웨어를 먼저 만든다.** 데이터와 학습에 너무 집중하지 않는다.

| 지금 앞으로 당길 것 | 이유 |
|---|---|
| 2번 물리 영역 확장 (두 번째 영역과 Studio 대화 확장) | 쓸 수 있는 영역이 늘어난다. 입력만 있으면 엔진이 계산하므로 실측 자료가 없어도 가상 분석이 된다 |
| 4번 Fab 꾸리는 곳, 5번 Physics 작업대 다듬기 | 사람이 직접 써 보는 소프트웨어가 된다 |
| 6번 서비스 외부 공개 준비 (인증, 저장) | 밖에서 열어 볼 수 있게 된다 |
| 3번 가운데 PINN (해석해를 아는 문제부터, 역문제까지) | 방정식 잔차로 학습하므로 실측 없이 시작하고, 해석해와 맞으면 증거 수준 E2를 정직하게 얻는다 |

1번(실측 대조)과 3번(학습)은 취소가 아니라 나중으로 넘긴다. **예외는 PINN이다.** PINN은 방정식의 잔차로 학습해 실측 자료 없이 시작할 수 있으므로 앞당긴다(위 표의 마지막 줄). 신경 연산자와 대리모형 같은 데이터 기반 학습만 나중이다. 1번이 3번의 전제라는 관계와 "학습한 모형은 물리가 정한 한계 안에서만 쓴다"는 원칙은 그대로다. 그동안 모든 결과는 "검증 전"으로 표시한다.

## 6. 숨은 상태 추정의 신뢰 구조 (2026-11-24 추가)

| 순서 | 할 일 | 상태 |
|---|---|---|
| 1 | 편차를 관측·모형·보정 항목으로 나누어 보고한다 (오차 예산). 합성 자료 04번의 토크계수와 마찰계수 연결이 첫 사례 | 예정 |
| 2 | 추정에 식별 가능성 점검을 더한다 (지금은 상대 불확도 기준 하나). 마찰, 컴플라이언스, 체결력을 조금씩 흔든 민감도 행렬의 유효 순위와 조건수를 내고, 부족하면 "토크 수준을 하나 더", "하중셀 병행" 같은 추가 관측을 권고한다 | 예정 |
| 3 | 위험을 안전율만이 아니라 추정 분포에서 낸 초과 확률로도 보고한다 | 예정 |
| 4 | 측정 CSV 보고서에 관측 근거 등급을 적는다 (합성은 가장 낮은 등급). 표현은 등급을 올리지 못한다 | 예정 |
| 5 | 답의 숫자, 단위, 개정이 근거 묶음에 있는지 확인하는 공통 점검을 만든다 (지금은 진단 대화에만 있다) | 예정 |

## 9. 이 문서를 고치는 때

결정이 나거나 과제가 끝날 때만 고친다. 고칠 때는 7번 결정 기록에 날짜와 함께 한 줄을 더하고, `config/status.yaml`과 어긋나지 않게 한다.
