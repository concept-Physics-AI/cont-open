# 개발 로드맵

> 상태: 정본

무엇을 어떤 순서로 만들고, 무엇이 끝나야 다음으로 가는지를 정한다. **기간은 적지 않는다.** 순서와 전제와 끝났다고 말할 조건만 적는다. 구조는 ARCHITECTURE.md, 규칙은 CLAUDE.md가 먼저이며, 현재 상태의 기준은 `config/status.yaml`이다. 이 문서와 어긋나면 상태 파일이 현재 사실이고, 이 문서를 고친다.

## 1. 목표

| 제품 | 쓰는 사람 | 목표 |
|---|---|---|
| Studio | 물리를 모르는 AI 전문가와 일반인 | 현실의 물리를 근거로 정확하고 현실과 이어진 답을 주는 생성형 AI. 물리 영역을 가리지 않는다 |
| Physics | 해석 도구를 쓰는 설계자, 3D CAD 설계자, 소재 전공자 | 물리·설계·소재는 아는 전문가가 AI를 쉽게 쓰게 돕는 소프트웨어 |
| Fab | 자기 Physical AI를 갖고 싶은 사람과 조직 | 각자의 Physical AI와 자기 Fab을 쉽게 만들게 돕는다 |

세 제품은 같은 코어(엔진과 서비스)를 쓴다. 값은 엔진만 낸다.

## 2. 지킬 원칙

1. 검증하지 않은 값은 "검증 전"이라고 적는다. 기준 자료가 생기기 전에는 허용 오차를 정하지 않고 편차만 보고한다.
2. 검증 없이 학습하지 않는다. 학습한 모형은 물리가 정한 한계 안에서만 쓴다.
3. 과제 하나는 브랜치 하나, PR 하나다. 구조를 바꾸면 ARCHITECTURE.md를 먼저 고친다.
4. 데이터가 없으면 있는 것처럼 만들지 않는다. 합성 데이터는 합성이라고 적는다.
5. 외부에 열 때는 보안을 먼저 정한다. 인증 없는 서비스는 이 컴퓨터에서만 연다.

## 4. 과제와 끝났다고 말할 조건

| 순위 | 과제 | 전제 | 끝났다고 말할 조건 |
|---|---|---|---|
| 1 | 검증(C6)과 실측 대조 | 기준 자료: 표준 예제, 해석 기준값, 실측값 (출처가 있는 것만) | 기준 사례가 `config/reference/`에 들어가고, 계산 결과와의 편차가 사례별로 보고된다. 허용 오차는 이 시점에 프로파일로 따로 정한다. 합성 자료로 한 시험(합성 정답 복원, 잘못된 값을 넣으면 잔차가 커지는지 보는 음성 대조)은 이 조건을 채우지 않으며 따로 표시한다 |
| 2 | 물리 영역 확장 | 영역마다 기준 자료와 해석식의 한계 | 두 번째 영역이 Studio 대화에서 답하고, 그 영역의 한계와 검증 상태가 답에 나온다 |
| 3 | 학습(C7)과 학습된 모형 | 1번의 기준 사례 | 학습 근거(데이터, 물리 교사)가 기록되고, 적용 범위 밖에서는 쓰지 않는 장치가 있다. 학습은 물리 값과의 편차만 맡고, 범위 밖이면 물리 값으로 돌아간다. 학습과 검증 자료는 시료·로트 단위로 나누며 행을 무작위로 나누지 않는다 |
| 4 | Fab: 꾸리는 곳, 시나리오, 공장 화면 | "꾸린다"의 범위를 대표가 정함 | 사용자가 고른 물리 정보로 자기 화면 한 개를 만들어 낸다 |
| 5 | Physics: 전문가 작업 도구 | 해석 설계자 사용 후 고칠 점, 외부 해석 결과의 형식과 권리 확인 | 해석 설계자가 자기 해석 한 건을 가져와 같은 화면에서 본다 |
| 6 | 서비스 외부 공개와 운영 | 서버 접근 설정 정리, 공개 범위 결정 | 인증, 사용자 구분, 결과와 개정 저장, 속도 제한, 감사 기록이 있고 지정한 사람이 외부에서 쓴다 |
| 7 | 형상(C5) 확장 | CAD 엔진 실행 환경(Docker) | 볼트 조인트 밖의 형상 하나가 명세에서 파일까지 나온다 |

### 4-1. 세 분야 개발 계획서에서 가져온 과제 (제안, 대표 확인 전)

실측 자료 없이 합성 데이터로 시작할 수 있고, 한 번에 끝나지 않는 과제만 골랐다. 합성 데이터는 합성이라고 적고 실측 대조를 암시하지 않는다.

| 기호 | 과제 | 전제 | 끝났다고 말할 조건 |
|---|---|---|---|
| A | 공통 데이터 계약과 실행 저장 | ARCHITECTURE.md에 계약을 먼저 적는다 | 프로젝트·대상·작업·실행 ID와 단위·좌표계·채널 의미 규칙이 있고, 한 건이 입력 → 계산 → 비교 → 저장 → 재열기까지 이어진다. 입력을 바꿔 다시 계산하면 새 실행이 생기고 이전 실행은 그대로 남는다. 승인한 실행과 최신 실행을 구분해 연다 |
| B | 체결 곡선 패키지 | 합성 토크·각도·시간 곡선 (합성 표시) | 곡선을 재생하고 착좌점·구간 기울기·체결 시간을 단계로 나눈다. 현행 규칙(기준선)과 같은 시험셋에서 편차를 보고한다 |
| C | 평가 틀 | 없음 | 학습·보정에 쓰지 않은 데이터로 평가하고, 작업일·로트 단위로 나눈다. 미검출과 오경보를 따로 보고하며 기준선을 함께 둔다. 합격선은 만들지 않는다 |
| D | 열·접촉 확장 | 열 영역 슬라이스(열전도 풀이기) | 열변형과 접촉 하중 분포의 합성 예가 해석해 또는 격자 수렴으로 대조된다. 세 묶음으로 나눈다: B1 열 해석(대표 적층 구조, 해석해와 격자 수렴), B2 열변형(열팽창과 구속, 단순 기준 문제와 변형량 비교), B3 접촉·조건 비교(간극·기울기·하중, 적용 가정·수렴·하중 평형, A/B 화면). 첫 질문: 같은 형상에서 온도 조건과 헤드 기울기를 바꾸면 변형과 접촉 상태가 어떻게 달라지는가. 각 묶음의 결과는 S의 실행 저장소에 보관한다. 대표 형상 시제품 범위이며 실제 장비 보정과 접합 품질 예측은 계측·검사 자료가 있어야 한다 |
| E | 관절 동역학 팩 | 열 영역 슬라이스가 끝난 뒤 | 단일 관절의 중력·관성·마찰 모델이 합성 로그와 비교되고 목표와 실제 궤적의 잔차를 보고한다. 제어기는 건드리지 않는다 |
| F | 모델 기록과 복원 | 학습 슬라이스의 학습 기록 | 모델 버전과 평가셋을 고정해 기록하고 이전 버전으로 되돌린다 |
| G | 설치·백업·복원 시험 | A의 저장 형식 | 새 환경에서 설치하고, 재시작과 백업·복원 뒤에도 같은 결과가 열린다 |
| H | 시간·좌표 정렬 | A의 데이터 계약 | 채널마다 장치 시각과 기준 시각의 오프셋을 기록하고 원본을 덮어쓰지 않은 정렬본을 만든다. 누락·중복·역순을 구간별 품질 표시로 남기고, 하중과 압력처럼 관측 범위가 다른 값을 구분해 보존한다. 합성 신호에서 알려진 오프셋을 복원한다 |
| I | 자료 수집 파이프라인 | A, H | CSV 같은 파일 한 종류에서 원본 등록(해시) → 의미 매핑 → 정렬 → 전처리 → 단계 분할 → 입력 고정까지 이어진다. 단위나 센서 위치를 모르면 실행하지 않고 부족한 것을 알려 준다. 원본과 전처리본이 모두 남는다 |
| J | 계산 어댑터 공통 규약 | 열 영역 슬라이스의 팩 | 입력 검사, 준비, 실행, 결과 수집, 평가의 다섯 함수와 취소·시간 초과·오류 기록이 있고, 체결 팩과 열 팩이 같은 규약으로 돈다. 기존 solve 호출은 그대로 동작한다 |
| K | 작업 템플릿 등록 | J | 템플릿 하나(목적, 필수 자료, 허용 조건, 계산 단계, 검증 지표, 화면 구성, 지원 범위)를 설정 파일로 등록하면 실행 가능한 작업이 만들어진다. 지원 범위 밖이면 계산하지 않고 이유를 말한다 |
| L | 실행 상태와 중복 요청 | A | 대기·실행·완료·실패·취소 상태와 중복 요청 키가 있다. 같은 키의 요청은 같은 실행을 가리키고, 취소와 시간 초과가 상태에 남는다 |
| M | Fab 위젯 데이터 연결 | A, H | 위젯이 대상·영역·실행·시간 ID로 자료에 묶이고, 저장 후 다시 열면 같은 결과가 나온다. 영상·신호·3D가 공통 시간축을 따르되 측정 간격과 보간 여부를 보존한다 |
| N | LLM 설명의 숫자 대조 | 없음 | 설명문에 나온 숫자와 단위를 결과 객체와 대조하고, 결과에 없는 숫자가 있으면 설명을 내보내지 않는다 |
| O | 재사용 측정 | K | 새 분야나 사례를 붙일 때 새로 쓴 코드와 설정의 양, 재사용한 모듈을 기록하는 보고가 있다. 자료 변환, 화면, 물리, 학습 모델을 따로 센다 |
| P | 용량 계산기 | 없음 | 채널 수, 취득률, 값 크기, 영상 비트레이트, 보존 기간으로 저장 용량을 계산하고, 값은 설정에서 받는다. 문서의 계산 예와 일치한다 |
| Q | 열 영역 인접 사례 | 열 영역 슬라이스 | 열 팩의 설정만 바꿔 인접 사례 2~3개(예: 상품 내부가 늦게 식는 냉각 문제, 판의 가열)가 해석해나 격자 수렴과 대조된다. 새로 쓴 코드의 양을 O로 잰다 |
| R | 상태 문서와 코드의 일치 검사 | 없음 | 상태표와 구조 문서가 말하는 기능(있음, 없음)마다 코드에서 확인하는 시험이 있다. 증거 파일의 존재만 보지 않고 기능 이름까지 맞춘다. 불일치 세 건은 고쳤다 |
| S | 제품 완성 흐름: 실행 저장과 Fab 연결 (A, L, M을 묶음) | A | 체결 또는 열 문제를 계산하고, 결과를 Fab에 배치하고, 프로그램을 종료했다가 다시 열어 **같은 입력, 같은 모델 버전, 같은 결과**를 확인한다. 결과가 없으면 없다고 표시하고 다시 계산할지 고르게 하며, 다시 계산한 결과는 새 실행으로 남는다. 지금은 저장한 조건이 목록에 없으면 첫 예시 그림을 보이므로 이를 실행 ID 기반 복원으로 바꾼다. 단계: 저장 규격(프로젝트·대상·입력·모델·실행·결과) → 저장소와 실행 등록·조회 → 실행 목록·상세 화면 → 재계산·실패·재시작 → 복원·버전 변경·누락 자료 시험. 같은 입력을 다시 계산해도 실행 기록은 새로 남기고, 결과가 같다는 사실은 내용 해시로 확인한다. Fab 쪽은 위젯 연결 규격(대상 ID, 실행 ID, 물리량, 단위, 표시 설정), 기준 실행과 변경 실행 나란히 보기, 구성과 연결된 결과를 함께 복원, 각 위젯의 시간축 보존(여러 신호 공통 동기화는 H와 잇는다) |
| T | 실제 브라우저 시험 | S | 카드 선택, 조건 변경, 구성 저장, 새로고침, 재열기 뒤에 조건, 배치, 결과가 같은지 브라우저에서 확인한다. 지금 시험은 화면 코드에 필요한 문자열이 있는지만 본다. CI에는 별도 작업으로 둔다 |
| U | PINN 서비스 전환 | 열 영역 슬라이스 | 학습 작업과 사용자 질의를 나누고, 모델·설정·학습 기록(지문)을 저장해 다시 읽는다. 수렴 상태와 평가 결과를 함께 기록하고, 계산 시간·메모리 제한과 취소·실패 처리가 있다. 지금은 첫 요청에서 학습해 메모리에만 둔다 |
| V | 쌓인 PR의 통합 검증 | 대표 병합 | 쌓인 PR을 main에 합친 같은 버전에서 시험, 화면, 서비스, 설치·재시작을 확인한다. 개별 PR의 시험 통과와 구분해 기록한다 |
| W | 대화로 이미지·그래프·3D·4D를 차례로 만들고 고치기 | 실제 텍스트·이미지 공급자의 설정(아래 열린 결정), S의 실행 저장 | 사용자가 자연어로 대화하면 목적을 알아듣고 필요한 것만 묻고, 작업 순서(계획)를 정해 도구를 실행하고, 끝난 결과부터 화면에 보인다. "두 번째 그림만 바꿔", "앞 조건과 비교해", "재생을 느리게 해"는 해당 결과와 관련 작업만 고치고 이전 결과를 남긴다. 대화, 계획, 실행, 생성물에 ID를 붙여 어느 결과가 어느 입력과 작업에서 나왔는지 잇고, 종료 후 다시 열어 이어서 한다. 단위 시험은 가짜 공급자로, 실제 공급자와 실제 브라우저 인수는 따로 켜는 시험으로 하며 가짜 응답으로 생성 기능을 완료 처리하지 않는다 |

| X | 세 화면의 개편: 대화 → 결과 → 계산 검토 → 내 Fab 구성이 한 작업으로 이어지게 | S, W | 공개 화면을 직접 조작해 검토한 결과를 반영한다. 세 화면 위쪽에 프로젝트, 현재 대상, 조건 버전, 저장 상태, 연결 상태가 같이 보이고, Studio에서 분석한 대상과 조건이 Physics와 Fab에서 다시 입력 없이 열린다. 요청과 관계없는 이전 결과(예: 본딩을 물었는데 M10 볼트 결과)를 새 답으로 보이지 않는다 |

## 5. 앞뒤 관계

- 1번이 3번과 5번의 소재 부분의 전제다.
- 2번은 Studio와 Physics가 함께 쓰므로 1번과 같이 간다.
- 6번 가운데 서버의 열린 포트 정리는 공개 여부와 관계없이 먼저 한다.
- 3번은 1번이 끝나기 전에는 시작하지 않는다.

**순서 조정 (2026-11-24 대표 결정): 쓸 수 있는 소프트웨어를 먼저 만든다.** 데이터와 학습에 너무 집중하지 않는다.

| 지금 앞으로 당길 것 | 이유 |
|---|---|
| 2번 물리 영역 확장 (두 번째 영역과 Studio 대화 확장) | 쓸 수 있는 영역이 늘어난다. 입력만 있으면 엔진이 계산하므로 실측 자료가 없어도 가상 분석이 된다 |
| 4번 Fab 꾸리는 곳, 5번 Physics 작업대 다듬기 | 사람이 직접 써 보는 소프트웨어가 된다 |
| 6번 서비스 외부 공개 준비 (인증, 저장) | 밖에서 열어 볼 수 있게 된다 |
| 3번 가운데 PINN (해석해를 아는 문제부터, 역문제까지) | 방정식 잔차로 학습하므로 실측 없이 시작하고, 해석해와 맞으면 증거 수준 E2를 정직하게 얻는다 |

1번(실측 대조)과 3번(학습)은 취소가 아니라 나중으로 넘긴다. **예외는 PINN이다.** PINN은 방정식의 잔차로 학습해 실측 자료 없이 시작할 수 있으므로 앞당긴다(위 표의 마지막 줄). 신경 연산자와 대리모형 같은 데이터 기반 학습만 나중이다. 1번이 3번의 전제라는 관계와 "학습한 모형은 물리가 정한 한계 안에서만 쓴다"는 원칙은 그대로다. 그동안 모든 결과는 "검증 전"으로 표시한다.
