## 현재 실행 우선순위 (2026-11-25 대표 확정)

제품 정의는 [ARCHITECTURE.md](../ARCHITECTURE.md)의 여섯 핵심 기능을 따른다. 아래 P1~P6은 현재 실행 순서이며, 뒤의 번호 1~7·A~Z는 기존 작업을 추적하는 식별자다. 산업별 학습·실측 대조가 이 흐름을 막지 않는다.

**생성형 최우선, 다양한 물리·숨은 물리·물리 잔차 PINN 자체 모형 SW의 무학습 병행 구현, 모형 학습과 대규모 현장 학습은 후속.** P1~P6을 먼저 연결하는 제품 목표와 PINN 병행 과제를 구분한다. 상세 기준은 [아키텍처의 개발 방향](../ARCHITECTURE.md)을 따른다. PINN의 모형 구조·잔차/관측 연산·기준 계산·저장/화면 연결을 학습 없이 인수한다. 미학습 신경망 출력은 물리 예측값으로 사용하지 않는다. 사용자 입력·샘플·저장·오류 기록·회귀 검사는 현재 범위다.

| 순서 | 지금 연결할 작업 | 기존 과제 | 인수 증거 |
|---|---|---|---|
| P1 | 실제 LLM 연결·문맥·프로젝트/사용자 구분 | W1~W2, R01·R03, X5 | 실제 공급자의 다중 턴, 정정·대상 참조·세션 격리 기록 |
| P2 | 계획 생성 → 도구 실행 → 진행 표시 | W3, R02·R05 | 실제 LLM 계획과 등록 도구 실행, 실패·취소·재시도 기록 |
| P3 | 설명·이미지·도식·그래프·3D·4D 생성 연결 | W4~W5, R14·R15·R30·R31 | 실제 산출물과 같은 대상의 장면; 그래프 원본값 대조 |
| P4 | 선택한 부분 수정·관련 결과만 갱신 | W6, R34 | 부품/영역/단계 선택, 변경 전후와 변경하지 않은 부분 비교 |
| P5 | 같은 대상·조건·버전·시간축 유지 | X5·X8, R09·R32 | 설명·그래프·장면의 참조 일치, 오래된 결과 혼입 차단 |
| P6 | 저장·재열기·작업 재개 및 실제 화면 인수 | S·T, W6~W7, R03·R37 | 종료 후 대화·조건·산출물·선택·카메라·재생 상태 복원 |

P1~P6은 사용자 흐름의 순서다. 저장 ID·버전·의존성 계약과 최소 저장소는 P1~P2부터 함께 준비하고 P6에서 전체 복원을 인수한다. M03의 입력 검증은 각 입력 도구와 함께 붙이며 M02 검색은 근거가 필요한 기능에 연결한다. PINN의 다양한 물리·숨은 물리·물리 잔차 개발은 아래 병행 과제로 진행한다. M05~M09의 대규모 현장 데이터 학습은 소프트웨어 인수 이후로 둔다.

첫 완성본은 본딩 설명 → 구조 이미지 → 층별 3D → 접근·정렬·접촉 4D → 두 번째 단계 속도·시점 수정 → 저장·재열기의 실제 사용자 흐름이다. 상세는 [generative_workflow.md](generative_workflow.md). 차별화 가설과 비교 평가 방법은 [differentiation.md](differentiation.md)(검증할 가설이며 확정된 성능 주장이 아니다)이고, 이를 지원하는 작업은 Y8(평가 틀)·Y9(공통 대상 명세)다.

무엇을 어떤 순서로 만들고, 무엇이 끝나야 다음으로 가는지를 정한다. **기간은 적지 않는다.** 순서와 전제와 끝났다고 말할 조건만 적는다. 구조는 ARCHITECTURE.md, 규칙은 CLAUDE.md가 먼저이며, 현재 상태의 기준은 `config/status.yaml`이다. 이 문서와 어긋나면 상태 파일이 현재 사실이고, 이 문서를 고친다.

### 작업 단위 실행과 인수 계획

P1~P6과 PINN 병행 범위를 실행하는 상세 명세는 [integration_control_plan.md](integration_control_plan.md), 작업별 의존·역할·재사용·산출물·인수·실패 시험·복귀는 [integration_jobs.yaml](integration_jobs.yaml)에 있다. CT 6개·GF 14개·PF 8개·QA 4개, 총 32개이며 제품 방향이나 현재 기능 상태를 대체하지 않는다. 모든 작업은 계획으로 등록했고 담당 배정과 실제 인수는 아직이다. CT01 → GF01/GF02 및 PF01/PF02를 첫 착수 묶음으로 삼고 컨트롤타워 전체 완성을 기다리지 않는다.

### PINN 무학습 소프트웨어 병행 과제

현재는 새 학습 실행이나 학습된 가중치 없이 자체 모형의 구조와 동작을 먼저 구현한다. [상세 PF01~PF08 작업](integration_jobs.yaml)이 기준이다. 열·구조·진동·유동 각각 문제와 모형 구성·잔차 함수·기준 계산을 준비하며, 생성형 인수는 이 표 전체의 완료를 기다리지 않는다.

| 과제 | 현재 구현 | 인수 증거 |
|---|---|---|
| 다양한 물리 | 문제·네트워크·초기/경계·물성·단위·좌표·시간·출력 계약 | 학습 호출 0으로 생성·입출력·미분/잔차 연산·저장 실행 |
| 숨은 물리 | 관측 연산·미지값·범위·민감도/식별가능성 인터페이스, 기존 해석 역산 | 기준 상태/관측 비교. 미지원 추정/불확실성은 값 없음 |
| 물리 잔차 | 방정식/경계/초기/보존/관측 잔차와 보정 입출력 | 알려진 기준해와 수치해에서 연산·단위·표시 확인. 학습 보정 없이 동작 |
| 생성형 연결 | 기준 물리 계산→그래프·3D·4D·조건 수정·저장 | 계산 방법·좌표·시간·대상 버전 보존; 미학습 출력 혼입 없음 |
| 실행·상태 | 조회 중 자동 학습 제거, 모형 상태와 기준 계산 경로 분리 | 가중치 없이 생성·조회·복원, 학습 경로를 막아도 인수 통과 |

PINN의 실제 파라미터 학습·성능 평가와 대규모 현장 데이터 학습은 후속 단계다. 기존 학습 연구 코드와 회귀 시험을 보존하되 무학습 SW 인수와 별도로 보고한다.

## 1. 목표

| 제품 | 쓰는 사람 | 목표 |
|---|---|---|
| Studio | 물리를 모르는 AI 전문가와 일반인 | 현실의 물리를 근거로 정확하고 현실과 이어진 답을 주는 생성형 AI. 물리 영역을 가리지 않는다 |
| Physics | 해석 도구를 쓰는 설계자, 3D CAD 설계자, 소재 전공자 | 물리·설계·소재는 아는 전문가가 AI를 쉽게 쓰게 돕는 소프트웨어 |
| Fab | 자기 Physical AI를 갖고 싶은 사람과 조직 | 각자의 Physical AI와 자기 Fab을 쉽게 만들게 돕는다 |

세 제품은 같은 코어(엔진과 서비스)를 쓴다. 값은 엔진만 낸다.

## 2. 지킬 원칙

1. 검증하지 않은 값은 "검증 전"이라고 적는다. 기준 자료가 생기기 전에는 허용 오차를 정하지 않고 편차만 보고한다.
2. 현재 PINN 소프트웨어는 새 학습 없이 구현·인수한다. 후속 모형 학습과 대규모 현장 데이터 학습은 필요한 범위를 정해 진행하며 각 학습은 평가 계획과 기준모형을 갖춰 시작하고, 물리 예측을 제품에 쓸 때는 적용 범위와 검증 근거를 확인한다. 이 조건을 대화·생성·편집 기능 개발의 선행조건으로 확대하지 않는다.
3. 과제 하나는 브랜치 하나, PR 하나다. 구조를 바꾸면 ARCHITECTURE.md를 먼저 고친다.
4. 데이터가 없으면 있는 것처럼 만들지 않는다. 합성 데이터는 합성이라고 적는다.
5. 외부에 열 때는 보안을 먼저 정한다. 인증 없는 서비스는 이 컴퓨터에서만 연다.

## 4. 과제와 끝났다고 말할 조건

| 기존 ID | 전문·기반 과제 | 전제 | 끝났다고 말할 조건 |
|---|---|---|---|
| 1 | 검증(C6)과 실측 대조 | 기준 자료: 표준 예제, 해석 기준값, 실측값 (출처가 있는 것만) | 기준 사례가 `config/reference/`에 들어가고, 계산 결과와의 편차가 사례별로 보고된다. 허용 오차는 이 시점에 프로파일로 따로 정한다. 합성 자료로 한 시험(합성 정답 복원, 잘못된 값을 넣으면 잔차가 커지는지 보는 음성 대조)은 이 조건을 채우지 않으며 따로 표시한다 |

| 4 | Fab: 꾸리는 곳, 시나리오, 공장 화면 | "꾸린다"의 범위를 대표가 정함 | 사용자가 고른 물리 정보로 자기 화면 한 개를 만들어 낸다 |
| 5 | Physics: 전문가 작업 도구 | 해석 설계자 사용 후 고칠 점, 외부 해석 결과의 형식과 권리 확인 | 해석 설계자가 자기 해석 한 건을 가져와 같은 화면에서 본다 |

연결 순서: 대화 → 계획 → 생성 → 화면 표시(진행과 완성 결과를 순서대로) → 화면 선택 → 재수정 → 저장.

**첫 완성본의 기준 장면** (하이브리드 본딩):
"과정을 설명해줘" → 설명과 작업 순서 제시 → "구조 이미지를 만들어줘" → 이미지 생성 → "층별 구조를 3D로 보여줘" → 같은 구조의 3D 장면 → "접근·정렬·접촉 과정을 움직여줘" → 시간에 따른 4D 장면 → "두 번째 단계만 느리게 하고 회전해서 보여줘" → 해당 장면만 수정 → "이 프로젝트를 저장해줘".

- 공정 동작을 설명하는 4D 장면은 먼저 구현한다. 온도·응력·변형의 수치까지 보이려면 그때 계산·측정 결과를 연결한다(생성 이미지와 장면 애니메이션을 물리 근거로 쓰지 않는다).
- 중심 모형: M01 대화·계획, M03 입력 이해, M04 이미지 생성·편집, M10 그래프·3D·4D 구성과 프로젝트 관리. M02는 근거를 보강하고, M05~M09는 필요한 산업 기능부터 연결한다.
- 이 정정으로 달라지는 것: 본딩(M07)을 "첫 산업 완성 대상"으로 먼저 파던 순서를 늦추고, 본딩은 위 기준 장면의 소재로 쓴다.

### 4-1. 기존 세부 과제 목록 (현재 우선순위에 따라 연결)

아래는 보존하는 과제 목록이며 현재 착수 지시가 아니다. PINN 병행 과제의 구조·잔차/관측 연산·기준 계산은 새 학습 없이 구현하며, 모형 학습과 대규모 현장 데이터 학습은 이후 검토한다. 합성 입력으로 소프트웨어의 입출력·렌더링을 시험할 수 있으며 합성 자료를 실측으로 표시하지 않는다.

| 기호 | 과제 | 전제 | 끝났다고 말할 조건 |
|---|---|---|---|
| A | 공통 데이터 계약과 실행 저장 | ARCHITECTURE.md에 계약을 먼저 적는다 | 프로젝트·대상·작업·실행 ID와 단위·좌표계·채널 의미 규칙이 있고, 한 건이 입력 → 계산 → 비교 → 저장 → 재열기까지 이어진다. 입력을 바꿔 다시 계산하면 새 실행이 생기고 이전 실행은 그대로 남는다. 승인한 실행과 최신 실행을 구분해 연다 |

| I | 자료 수집 파이프라인 | A, H | CSV 같은 파일 한 종류에서 원본 등록(해시) → 의미 매핑 → 정렬 → 전처리 → 단계 분할 → 입력 고정까지 이어진다. 단위나 센서 위치를 모르면 실행하지 않고 부족한 것을 알려 준다. 원본과 전처리본이 모두 남는다 |

Fab 쪽은 위젯 연결 규격(대상 ID, 실행 ID, 물리량, 단위, 표시 설정), 기준 실행과 변경 실행 나란히 보기, 구성과 연결된 결과를 함께 복원, 각 위젯의 시간축 보존(여러 신호 공통 동기화는 H와 잇는다) |

"두 번째 그림만 바꿔", "앞 조건과 비교해", "재생을 느리게 해"는 해당 결과와 관련 작업만 고치고 이전 결과를 남긴다. 대화, 계획, 실행, 생성물에 ID를 붙여 어느 결과가 어느 입력과 작업에서 나왔는지 잇고, 종료 후 다시 열어 이어서 한다. 단위 시험은 가짜 공급자로, 실제 공급자와 실제 브라우저 인수는 따로 켜는 시험으로 하며 가짜 응답으로 생성 기능을 완료 처리하지 않는다 |

### 과제 Y: AI 기능 M01~M10의 역할 (핵심 흐름과 전문 기능)

제품화에 필요한 AI 기능을 열 개로 나누고, 어느 것을 자체 학습하고 어느 것을 기존 기반모형으로 먼저 끝낼지 정한다. 열 개가 각각 독립된 거대모형이라는 뜻은 아니다. 아래 수량과 목표치는 착수용 제안이며 달성 실적이나 확정된 기준이 아니다. 기준선과 현장 요구 오차를 먼저 측정한 뒤 인수 기준으로 확정한다.

| ID | 기능 | 방식 | 이 저장소의 지금 위치 (착수 때 코드와 다시 대조) |
|---|---|---|---|
| M01 | 대화·작업 계획 | 기존 LLM + 구조화 출력 + 실행기. 반복 실패가 데이터로 확인되면 미세조정 | `cont.llm` 어댑터와 `cont.dialogue`가 있다. 실제 공급자 연결과 다중 턴 계획은 과제 W |
| M02 | 제조 지식·근거 검색 | 기존 임베딩·재순위 모형 | 없음. 문서 종류, 버전, 접근 권한을 먼저 정한다 |
| M03 | 도면·이미지·표 이해 | CSV 직접 파싱, OCR, VLM은 후보 제안만, 단위 사전과 허용 범위로 검증 | CSV 읽기는 `cont.signal`에 있다. OCR·VLM은 없음 |
| M04 | 설명 이미지 생성·편집 | 기존 이미지 생성모형 연결. 그래프와 물리장은 생성 이미지로 대신하지 않는다 | 과제 W4, 열린 결정(공급자) |

| M07 | 본딩 열·변형·품질 | A 열응답, B 열변형·정렬, C 접합 품질을 입력과 정답이 다른 세 과제로 나눈다. 온도만으로 접합 품질을 보증하지 않는다 | A의 기준(해석식, 유한차분, PINN 비교)이 열 슬라이스에 있다. B와 C는 없음 |

제품 개발의 중심은 M01·M03·M04·M10과 프로젝트 관리다. M02는 근거를 보강하고 M05~M09는 필요 시 연결하는 전문 기능이다. 기반모형을 연결해 여섯 핵심 동작을 먼저 완성하고 실제 사용 평가를 진행한다. 그 이후의 자체 학습은 도구 선택·선택 편집·대상 일관성 등 실제 실패가 쌓인 지점과 전문 모델을 각각 평가해 정한다. 이미지·대화 기반모형의 대규모 사전학습을 첫 제품의 전제로 두지 않는다.

## 5. 앞뒤 관계

- 대화·생성·선택 편집은 실측 자료와 산업별 학습 없이 시작한다. 실제 모델 연결과 실제 산출물은 필요하다.
- 설명용 4D는 형상·단계·카메라·재생 시퀀스로 구현한다. 이를 물리 해석·측정 결과로 표시하지 않는다.
- 물리 수치가 필요한 요청만 해당 팩·측정·검증에 의존한다. 지원하지 않는 계산은 부족한 정보를 알리되 가능한 설명·구조 생성 작업은 계속한다.
- 프로젝트·산출물 ID, 부모 버전, 의존성, 선택 상태 계약은 초기에 두고 저장·재개를 흐름 전체에서 시험한다.
- PINN은 다양한 물리·숨은 물리·물리 잔차의 자체 모형 SW와 화면 연결을 새 학습 없이 병행한다. 실제 신경망 학습은 후속으로 둔다. 대규모 현장 데이터 구축·학습은 소프트웨어 인수 이후로 둔다. 기존 연구 코드를 보존하고 후속 현장 학습의 데이터 분할·독립 검증 원칙을 유지한다.
- 외부 공개의 인증·사용자 격리는 공개 전에 갖춘다. 로컬 개발과 설명용 생성까지 외부 공개 승인에 묶지 않는다.
