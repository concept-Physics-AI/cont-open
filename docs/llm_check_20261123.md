# 실제 LLM으로 돌려 본 기록 (2026-11-23, 대표 PC)

대화 기능은 그동안 가짜 응답으로만 시험했다. 이 기록은 대표 PC에서 실제 모델로 처음 돌려 본 결과다.

- 환경: Windows, RTX 5080 Laptop GPU 16GB, Ollama, 모델 `gpt-oss:20b` (`config/llm`의 `ollama_local`)
- 방법: 체결 대화 7마디, 진단 묻고 답하기 4문항을 각각 한 번씩. 같은 질문을 여러 번 돌려 흔들림을 재지는 않았다.

## 체결: 말에서 바꿀 항목 읽기

| 말 | 모델이 읽은 것 | 맞음 |
|---|---|---|
| 토크를 60으로 올려줘 | 조임 토크 60 | 예 |
| 볼트를 M12로 바꾸고 머리 쪽 판은 20mm로 | 규격 M12, 머리 쪽 판 두께 20 | 예 |
| 축방향 하중을 12 kN으로 | 축방향 하중 12000 N | 예 |
| 볼트가 늘어나지 않게 항복 안전율 1.5 이상, 미끄럼 안전율 2.5 이상이 되게 해 줘 | 목표 두 개 (추천만, 변경 없음) | 예 |
| 첫 번째 걸로 하자 | 1번 선택 | 예 |
| 오늘 점심 뭐 먹을까 | 바꿀 것 없음 | 예 |
| M7로 바꿔 | 규격 M7 → 표준 데이터에 없어 거절, 조인트 그대로 | 예 |

7마디 모두 맞게 읽었다. 한 마디에 0.5~3초. 모델을 처음 올릴 때는 53초가 걸렸다.
계산은 모두 체결 팩이 했다. 모델은 항목만 골랐다.

## 진단: 결과를 말로 다듬기

첫 실행에서, 숫자 검사(진단 사실에 없는 숫자를 막는 검사)를 통과했는데도 틀리거나 지나친 답이 나왔다.

| 본 문제 | 예 | 조치 |
|---|---|---|
| 시각 값에 단위를 지어냄 | "1205시" | 지시문에 금지, 검사 추가 (규칙 답으로 돌아감) |
| 숫자를 다른 신호에 붙임 | 유량이 "1205 시점에서" 줄었다고 함 (실제는 1500) | 지시문에 "그 신호, 그 구간과 짝지어"를 추가. 검사로는 막지 못한다 |
| 원인의 예를 스스로 듦 | "밸브 손상, 누수 등" | 지시문에 금지 |
| 확률로 말함 | "가능성이 높습니다" | 지시문에 금지, 검사 추가 |
| "~배까지"를 "이상"으로 바꿈 | "15.6배 이상" | 지시문에 설명 추가 |
| 꾸밈 기호 | `**1205시**` | 기호를 지움 |

지시문과 검사를 고친 뒤 다시 돌린 결과: 네 문항 모두 숫자와 구간이 진단 사실과 맞았고, 원인은 "후보"로만 말했다.
다만 표현이 느슨한 곳은 남았다 (예: "정상 산포의 11.3배까지"를 "최대 +11.3배 상승"으로 줄여 말함).

## 결론

- **체결의 말 읽기는 실제 모델로 쓸 만하다.** 모델이 틀려도 허용한 항목·형식 검사와 팩의 재계산이 뒤에 있다.
- **진단의 말 다듬기는 검사만으로 안심할 수 없다.** 숫자가 맞아도 숫자와 신호의 짝이 틀릴 수 있고, 이것은 지금 검사로 잡지 못한다.
  그래서 LLM이 다듬은 답 아래에 근거로 쓴 진단 사실을 그대로 붙여, 읽는 사람이 대조할 수 있게 했다.
- 한 번씩만 돌렸다. 모델의 답은 돌릴 때마다 달라질 수 있으니, 시연 전에 같은 질문을 여러 번 돌려 봐야 한다.
- 다른 모델(`mpai-gpt-oss-20b`, 외부 API)로는 돌려 보지 않았다.
