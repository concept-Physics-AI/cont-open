# AI 기능 M01~M10과 이 저장소의 대조표

> 상태: 참고

## 현재 제품 우선순위

2026-11-25 대표 확정: **M01·M03·M04·M10과 프로젝트 관리가 핵심**, M02는 근거 보강, M05~M09는 필요 시 연결하는 전문 기능이다. 아래 M 번호와 60개 작업 번호는 식별자이며 중요도나 착수 순위가 아니다. 현재는 기존 모델의 추론으로 생성형 소프트웨어를 완성한다. PINN의 다양한 물리·숨은 물리·물리 잔차 자체 모형 SW는 새 학습 없이 병행 구현한다. 실제 신경망 학습은 후속으로 둔다. 대규모 현장 데이터 구축·라벨링·학습은 소프트웨어 인수·실제 사용 평가 이후로 둔다. 핵심 생성형 모델의 미세조정도 실제 사용에서 필요를 확인한 뒤 검토한다. 사용자 입력·샘플 처리와 소프트웨어 시험은 지금 수행한다. 여섯 핵심 동작과 첫 인수 흐름은 [generative_workflow.md](generative_workflow.md)를 따른다.

로드맵 과제 Y의 첫 단계(Y1)다. M01~M10은 제품화에 필요한 AI 기능 열 개의 제안이고([roadmap.md](roadmap.md) 과제 Y), 이 문서는 그 하나하나가 **지금 코드에 있는지**를 적는다. 있는 것은 파일 경로를, 없는 것은 "없음"을 적는다. 없는 것을 있는 것처럼 적지 않는다. 코드를 바꾸면 이 표도 같이 고친다.

구분은 네 가지다: **있음**(코드와 시험이 있다), **일부**(일부만 있고 빠진 것을 적는다), **연결만 필요**(기반 도구는 있고 제품에 잇는 일이 남았다), **없음**.

## 읽는 법

- 열 PINN은 선택 설치 연구 모형이며 모델 파일은 커밋하지 않고 서비스에서는 문지기를 거친다([physics_models.md](physics_models.md)). M05의 경량 트리와 M06의 선형 보정은 합성 자료로 맞추는 실험 코드가 있다. 실측으로 평가한 산업별 학습 모형은 아직 없다.
- 소프트웨어 인수 이후 M05~M09의 대규모 현장 데이터 학습을 검토할 때는 먼저 기준모형을 같은 시험에 올리고 학습 모형과 비교한다. 위 표에서 "일부"인 칸의 기준모형이 그 출발점이다.
- 합성 자료와 실측 자료를 섞어 성능을 말하지 않는다. 지금 이 저장소에는 현장 실측 자료가 없다.

## 상세 명세가 정한 공통 계약 (제안)

명세는 공통 객체를 일곱 개 제안한다: RequestContext(project, conversation, scope, scenario, revision), InputRef(dataset 또는 artifact, 버전, 출처 종류, 체크섬), Quantity, ModelRequest, ModelResult, Applicability(지원 범위, 범위 밖, 빠진 입력), ExecutionEvent(순서, 작업, 단계, 상태). 이 저장소와 맞출 때 정할 것:

| 명세의 객체 | 이 저장소의 지금 것 | 정할 일 |
|---|---|---|
| Quantity | `cont.answer.Quantity`가 이미 있고 권위 표가 같은 이름의 재정의를 막는다 | 이름을 새로 만들지 않는다. 명세의 좌표계, 변환 이력, 불확실도 참조가 필요한 만큼 기존 것에 더할지 별도 이름으로 둘지 정한다 |
| ModelResult의 run_id, 버전, 상태 | `Provenance`, 실행 저장소(`cont.service.runs`)의 실행 기록 | 상태에 "성공, 실패, 지원 범위 밖"을 구분해 넣는다 |
| Applicability | `PhysicsAnswer.scope`, `failure_conditions` | 문자열이 아닌 구조(범위, 빠진 입력)가 필요한지 정한다 |
| ExecutionEvent | 없음 (과제 L의 실행 상태와 W3의 실행기) | 중복 수신과 재접속에도 같은 상태가 나오게 만든다 |
| RequestContext, InputRef | 없음 (프로젝트 개념은 과제 A·X5) | 프로젝트와 시나리오 계약을 먼저 정한다 |

신뢰 정보는 하나의 `confidence`로 합치지 않는다. 문서 검색 점수, 분류 확률, 측정 불확도, 예측구간, 모형 적용 범위는 다른 항목이고, LLM이 스스로 적은 신뢰 점수는 교정된 확률로 쓰지 않는다. 지금 `Confidence`(high, medium, low와 이유)는 팩이 규칙으로 채우는 것이며 이 구분과 충돌하지 않는지 Y2에서 확인한다.

명세에서 이 저장소에 아직 옮기지 않은 것: 모듈별 목표 수치(성공률 90%, 인자 정확도 95%, Recall@5 90% 등), 18주 일정과 인력 가정(로드맵은 기간을 적지 않는다), 하이퍼파라미터 후보(TCN 블록 수와 채널 수, 문서 분할 길이 등). 모두 첫 기준선을 잰 뒤에 대표가 확정한다.
