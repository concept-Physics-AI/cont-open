# 필수 AI 모형 M01~M10과 이 저장소의 대조표

> 상태: 참고

로드맵 과제 Y의 첫 단계(Y1)다. M01~M10은 제품화에 필요한 AI 기능 열 개의 제안이고([roadmap.md](roadmap.md) 과제 Y), 이 문서는 그 하나하나가 **지금 코드에 있는지**를 적는다. 있는 것은 파일 경로를, 없는 것은 "없음"을 적는다. 없는 것을 있는 것처럼 적지 않는다. 코드를 바꾸면 이 표도 같이 고친다.

구분은 네 가지다: **있음**(코드와 시험이 있다), **일부**(일부만 있고 빠진 것을 적는다), **연결만 필요**(기반 도구는 있고 제품에 잇는 일이 남았다), **없음**.

| ID | 기능 | 구분 | 코드에 있는 것 | 없는 것 |
|---|---|---|---|---|
| M01 | 대화·작업 계획 | 일부 | `cont.llm`의 공급자 어댑터(OpenAI 호환, Anthropic, Gemini)와 시험용 `Echo`. `cont.dialogue`의 체결·열·진단 대화 | 실제 공급자와 연결한 확인, 대상과 조건을 유지하는 다중 턴 문맥, 검증된 계획 객체와 실행기 (과제 W) |
| M02 | 제조 지식·근거 검색 | 없음 | 없음 | 문서 등록, 분할, 검색, 재순위, 근거 연결 |
| M03 | 도면·이미지·표 이해 | 일부 | CSV 읽기 `cont.signal.csvio`, 형상 읽기 `cont.shape`(STL, STEP) | OCR, VLM, 단위 사전 기반 검증, 열 의미 추출 |
| M04 | 설명 이미지 생성·편집 | 없음 | 공급자 어댑터는 글 응답만 다룬다. 계산으로 그린 그림은 `cont.view`, `cont.fab`에 있다 | 이미지 생성 공급자 연결 (열린 결정: 공급자, 어댑터 위치) |
| M05 | 공통 공정 신호 해석 | 일부 | 스펙트럼·피크·스펙트로그램 `cont.signal.analysis`, 조건별 정상 기준 `cont.packs.diagnosis.baseline`, 이상 구간 검출 `cont.packs.diagnosis.detect` | 공정 단계 인식, 학습 시계열 모형, 공통 표현 학습, 새 설비 전이 시험 |
| M06 | 체결 상태·품질 추정 | 일부 | 물리 기준 `cont.packs.fastening`(VDI 2230 기준 계산, 늘어남에서 체결력과 마찰 역추정 `estimate`, 조이는 과정 `process`) | 실측 축력으로 학습한 보정, 품질 분류, 실측 자료 |
| M07 | 본딩 열·변형·품질 | 일부 | 열 영역의 해석식과 유한차분 `cont.packs.heat`, 학습 후보 PINN `cont.learn`(선택 설치, 문지기 `gate`), 축대칭 유한요소 `cont.fem.axisym` | A: 적층 구조 열모형과 실측 비교. B: 열변형·정렬. C: 접합 품질. 대리모형 |
| M08 | 관절 운동·부하 | 없음 | 없음 | 운동학, 동역학, 시스템 식별 |
| M09 | 이상 근거·점검 제안 | 일부 | 진단 보고와 점검 안내 `cont.packs.diagnosis.report`, `guidance`, 추세 `trend` | 원인 후보 순위(확인된 정비 사례가 필요), 확률 보정 |
| M10 | 그래프·3D·4D 구성 계획 | 일부 | 결과를 그리는 렌더러: Fab 미리보기와 3D 돌려 보기 `cont.fab`, 화면 `cont.view` | LLM이 쓰는 장면 사양(스키마, 차원 검사), 그래프와 장면의 시점 동기화 (과제 W5, X8) |

## 읽는 법

- 학습한 모형은 지금 열 PINN 하나뿐이고, 모델 파일은 커밋하지 않으며 서비스에서는 문지기를 거친다([physics_models.md](physics_models.md)). M05~M09의 학습 모형은 아직 없다.
- M05~M09는 먼저 기준모형을 같은 시험에 올리고 학습 모형과 비교한다. 위 표에서 "일부"인 칸의 기준모형이 그 출발점이다.
- 합성 자료와 실측 자료를 섞어 성능을 말하지 않는다. 지금 이 저장소에는 현장 실측 자료가 없다.
